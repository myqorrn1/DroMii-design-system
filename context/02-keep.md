# 그대로 쓸 것 / 고칠 것

디자인시스템은 **새로 만드는 일이 아니라 정리하는 일**입니다.
두 제품이 이미 잘 하고 있는 것을 갈아엎으면 시스템이 아니라 리디자인이 됩니다.

---

## 그대로 쓸 것 — 이미 옳게 하고 있는 것

### 1. D-ROAD의 다크 표면 체계 ★ 가장 중요

```
#2B2E3A  페이지 배경   19회
#272934  카드          35회
#343743  패널          52회
#484C5E  보더·떠 있는 표면   30회
```

**이미 일관된 4단 표면 체계가 있습니다.** 새로 만들 필요가 전혀 없어서
공통 중립 색상 단계의 700–950 구간을 이 값 그대로 채택했습니다.
D-ROAD 화면은 이 부분에서 손댈 게 없습니다.

### 2. 모달 폭 448px

D-ROAD에서 **9회 반복**돼 사실상 표준으로 굳어져 있고, 로그인 카드 폭과도 같습니다.
정한 값이 아니라 **발견한 값**입니다. 그대로 기본값으로 씁니다.

### 3. `#7E72E6` — 이미 존재하는 색상 단계 논리

누군가 `#9D91FF`의 hover 값으로 직접 계산해 넣어둔 값입니다.
**색상 단계 개념이 코드에 암묵적으로 이미 있다**는 뜻이라,
새로 만들지 않고 accent-600 자리에 그대로 넣었습니다.

### 4. `approval_btn` / `refusal_btn` 쌍

이름은 도메인 용어지만 실질은 **primary / danger 개념**입니다.
버튼 variant를 새로 발명한 게 아니라 이미 있던 구분에 이름을 붙였을 뿐입니다.

### 5. D-ROAD의 셸 분리 구조

`Header.jsx`(207줄) + `MenuBar.jsx`(78줄)로 이미 깔끔하게 분리돼 있습니다.
**셸 원형은 D-ROAD 쪽을 기준으로 삼습니다.** K-AQUAS가 이쪽에 맞추는 방향입니다.

### 6. K-AQUAS의 Pretendard 폰트 자산

`src/font/`에 woff2 9개가 이미 있습니다. 새 폰트를 고르지 않고
이 파일을 공용으로 옮기는 것만으로 CDN 의존과 제품 간 불일치를 함께 해결합니다.

### 7. K-AQUAS의 조밀한 밀도 (30px · 24px 컨트롤)

지도 위에 컨트롤을 얹는 화면이 많아서 생긴 **맥락 있는 선택**입니다.
D-ROAD(40–44px)에 맞춰 통일하면 지도 화면이 답답해집니다.
없앨 불일치가 아니라 **size 토큰으로 흡수**했습니다.

단 정확히 하자면 **sm 32는 코드에서 찾은 값이 아니라 반올림한 값입니다** —
실측 최다는 30px(23회)이고 4px 그리드에 맞춰 32로 올렸습니다.
2px 차이는 지도 컨트롤에서도 감당 가능하다고 판단했습니다.

**24px(14회)은 반올림하지 않고 `xs`로 따로 뒀습니다.** 대부분 지도 위 아이콘 버튼이라
32로 올리면 지도가 가려집니다. `xs`는 **아이콘 버튼 전용**이고 글자 버튼에는 쓰지 않습니다.

### 8. radius 4px

4px과 5px이 합쳐 **145회**로 압도적입니다. 이미 사실상의 기준입니다.
큰 요소의 10px 계열도 44회로 뚜렷해서 두 단계로 나눴습니다.

### 9. 도메인 상태 어휘

`승인대기 · 승인완료 · 승인거부` 같은 상태값은 업무 용어라 바꾸지 않습니다.
시각 표현(배지 색·형태)만 시스템으로 통일합니다.

### 10. K-AQUAS의 유역본부 소속 체계

한강·낙동강·금강·영섬유역본부는 K-water 조직 구조입니다. 데이터 모델이지 디자인이 아닙니다.

## 판단 기준

무엇을 그대로 둘지 정할 때 쓴 기준입니다. 앞으로 새 항목이 나와도 이 순서로 보면 됩니다.

1. **빈도** — 이미 많이 쓰이면 그게 사실상의 기준이다
2. **일관성** — 한 제품 안에서 일관되면 체계가 이미 있는 것이다
3. **맥락** — 다른 데는 이유가 있을 수 있다 (지도 화면의 밀도처럼)
4. **의도** — 브랜드·업무 용어는 디자인 판단 대상이 아니다

**반대로 이런 건 바꿉니다** — 라이브러리 기본값이 섞여 들어온 것,
임시방편으로 막아둔 것, 같은 뜻인데 값만 다른 것.
