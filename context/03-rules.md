# 시스템 규칙 — 앞으로 만들 것에도 적용

> v3 · 공용 시스템 기준선 (2026-09-10)

값보다 이쪽이 더 중요합니다. 새 컴포넌트를 만들 때 이 규칙으로 판단하면
누가 만들어도 같은 결과가 나옵니다.

---

## 1. 공통과 제품별의 경계

> **구조와 행동은 공통으로 두고, 표현 차이는 독립된 축으로 관리합니다.**

제품 이름 하나에 모든 차이를 묶지 않습니다. 공용 시스템은 다음 세 축을 조합합니다.

1. **브랜드** — 강조 색상과 제품 자산이 들어갈 자리
2. **명도** — 라이트 · 다크
3. **밀도** — compact · comfortable

버튼 구조, 폼 간격 규칙, 테이블 동작, 모달 구조, 상태와 오류 문구 원칙은 공통입니다.
K-AQUAS와 D-ROAD에서 확인한 크기 차이는 밀도 설정으로 흡수합니다. 제품별 기본 조합은
해당 제품 코드를 다시 확인한 뒤 프리셋으로 정합니다.

로고 분석은 이번 구축 범위에서 제외합니다. 컴포넌트는 제품 자산을 받을 자리만 제공합니다.

## 2. 역할 토큰만 참조한다

컴포넌트는 `accent-500` 같은 단계 번호를 **직접 쓰지 않습니다.**

```css
/* O */  background: var(--dm-primary-solid);
/* X */  background: var(--dm-accent-500);
```

두 제품의 브랜드 기준색이 서로 다른 명도 단계에 있기 때문입니다 —
K-AQUAS는 **500**, D-ROAD는 **400**. 다크 테마에서는 브랜드색이 배경보다 밝아야 해서
같은 번호에 놓을 수 없습니다. 번호를 직접 쓰면 D-ROAD에서 색이 어긋납니다.

## 3. 500은 배경 전용, 600은 글자용 — 시멘틱 색에 적용

채도 높은 색은 흰 글자와의 대비가 부족한 경우가 많습니다.
같은 색의 한 단계 아래를 **글자를 얹는 용도**로 따로 둡니다.

**적용 대상: 시멘틱 색(success · info · warning · danger)과 차트 색.**

**브랜드 강조 색상은 이 규칙을 따르지 않습니다.** 기준색이 색상 단계의 몇 번 자리에 오는지는
제품의 명도 방향에 따라 달라지기 때문입니다.

| 제품 | 기준색 | 색상 단계 위치 | solid |
|---|---|---|---|
| K-AQUAS | `#5098EC` | 500 | **500** — 어두운 글자와 5.96:1 |
| D-ROAD | `#9D91FF` | 400 | **400** — 어두운 글자를 얹어 6.70:1 확보 |

새 제품을 추가할 때도 "기준색을 몇 번에 놓고 solid를 어디로 할지"는
**명도와 대비를 계산해 정합니다.** 500/600을 기계적으로 적용하지 마세요.

## 4. 밀도 차이는 흡수한다

K-AQUAS 30px / D-ROAD 40–44px은 지도 화면 비중에서 온 **맥락 있는 차이**입니다.
통일하지 않고 size 토큰(sm 32 / md 40 / lg 44)으로 흡수하고,
제품별 기본 size만 다르게 둡니다.

## 4-B. 4px 그리드는 요소 사이에만 적용한다

간격 토큰(4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80)은
**요소와 요소 사이**에 씁니다.

**컴포넌트 내부 치수는 그리드 예외입니다.**

```
gap 5 · 6 · 7            버튼 아이콘↔글자 (size별)
badge-px 9               배지 좌우 여백
choice 18                체크박스 · 라디오
switch 36 / 20 / 16      트랙 · 높이 · 노브
control-h 24 / 32 / 40 / 44
```

전부 실측에서 나온 값이고, 이 자리에서는 **시각 균형이 그리드보다 우선**합니다.
18px 체크박스를 16이나 20으로 옮기면 13px 글자와 시각 중심이 어긋납니다.

새 컴포넌트를 만들 때도 내부 치수는 그리드에 억지로 맞추지 말고,
**요소 사이 간격만** 토큰을 쓰세요.

## 5. 명도 방향은 테마마다 반대

| | 라이트 | 다크 |
|---|---|---|
| hover | 어두워짐 | **밝아짐** |
| pressed | 더 어두워짐 | **어두워짐** |
| 떠 있는 표면(모달·토스트) | 그대로 흰색 + 그림자 | **한 단계 밝게** (`#343743`) |
| 모달 푸터 | 한 단계 낮게 | 한 단계 밝게 |
| 입력란 | 배경보다 **밝게** (흰색) | 배경보다 **어둡게** (`#1E2027`) |
| 비활성 텍스트 | muted 500 → disabled **400**(더 밝게) | muted 500 → disabled **600**(더 어둡게) |

기계적으로 뒤집으면 안 됩니다. 각 방향에 이유가 있습니다.

## 6. 행 상태는 명도가 아니라 색상으로 구분

테이블·목록의 hover와 선택은 **한 가지 기준으로만 나누면 구분이 안 됩니다.**

- hover = 중립 한 단계
- 선택 = 옅은 강조 색상

처음엔 라이트 선택을 `#ECF5FE`로 잡았는데 렌더링해보니 hover(`#EDEFF3`)와 거의
같아 보여서 `#D4E9FC`로 한 단계 올렸습니다. 다크는 강조 색상이 보라라 처음부터 문제없었습니다.

## 7. radius 두 단계만 기억한다

- **4px** — 버튼 · 입력 · 칩 · 카드 (작은 컨트롤)
- **10px** — 모달 · 다이얼로그 (떠 있는 큰 면)

나머지 넷(2 · 6 · 16 · full)은 예외용입니다.

## 8. 알림 3종의 역할이 다르다

| | 쓰는 때 | 사라지는가 |
|---|---|---|
| **토스트** | 이미 끝난 일. 놓쳐도 되는 정보 | 성공·정보 4초 후 |
| **배너** | 조건이 유지되는 동안 계속 보여야 하는 것 | 조건 해소까지 |
| **다이얼로그** | 답을 받아야 다음으로 갈 수 있을 때 | 사용자가 답할 때까지 |

서비스가 실제 되돌리기 기능을 제공할 때만 **토스트 + 실행취소**를 씁니다.
되돌릴 수 없는 파괴적 동작은 대상을 분명히 적은 다이얼로그로 확인합니다.

## 9. 빈 상태는 두 종류다

- **"아직 아무것도 없다"** → 만들기를 권한다
- **"찾지 못했다"** → 조건 푸는 길(필터 초기화)을 준다

현재 제품 코드의 로딩 표현은 스피너입니다. 스켈레톤은 실제 화면에서 필요성이 확인되고
완료·오류·빈 상태까지 동작이 정의될 때 시스템 컴포넌트로 추가합니다.

## 10. 색만으로 상태를 말하지 않는다

상태 배지는 **항상 글자를 동반**합니다.
색각 이상 사용자와 흑백 출력에서 "완료"와 "실패"가 구분돼야 합니다.

## 11. 브랜드색은 차트 계열 색이 아니다

`#9D91FF`는 OKLCH 명도 0.714로 다크 계열색 허용 대역(0.48–0.67)을 벗어납니다.
계산 결과 **사용 불가**입니다.

대신 **강조 색상은 순차형 색상 단계**가 됩니다 — 카테고리는 "무엇"이고 순차형은 "얼마나"인데,
두 제품의 주 지표(수질 등급 · 파손 심각도)는 후자입니다.
두 순차형 단계 모두 기존 강조 색상에서 그대로 뽑혔습니다.

차트 안에서 강조 색상은 **선택·hover 표시**에 씁니다 — 버튼과 같은 규칙입니다.

## 12. 문구 규칙

- **토스트 제목**은 일어난 일을 과거형으로. 본문은 맥락이나 다음 행동.
- **다이얼로그 제목은 질문으로.** "삭제 확인"이 아니라 "선택한 사용자 3명을 삭제할까요?"
  — 대상과 개수를 제목에 넣습니다.
- **본문은 결과를 말합니다.** 무엇이 사라지고 무엇이 남는지.
  "정말 삭제하시겠습니까?" 같은 되묻기는 정보가 없습니다.
- **버튼 라벨은 동사.** 확인/취소가 아니라 삭제 / 저장 / 승인. 제목의 동사와 같은 단어.
- 사과·변명 금지. "죄송합니다" 대신 무엇을 하면 되는지.

## 13. 포커스는 두 표현을 갖는다

한 요소에 둘을 겹치지 않습니다.

| 요소 | 표현 | 이유 |
|---|---|---|
| 입력 · 셀렉트 · 체크박스 · 라디오 · 칩 | 보더를 `focus-ring`으로 바꾸고 halo 3px | 이미 보더가 있으므로 밖에 링을 더 그리면 선이 두 겹이 된다 |
| 버튼 · 링크 | `outline 2px offset 2` | 보더가 없거나 투명해서 바꿀 선이 없다 |

halo 색은 `--dm-focus-halo`, 오류 상태에서는 `--dm-focus-halo-danger`로 바뀝니다.

## 14. 상태 전환에만 모션 토큰을 쓴다

`--dm-duration-fast`(120ms) 색·보더 · `--dm-duration-base`(200ms) 위치 이동 ·
`--dm-ease-out` 공용. 로딩 스피너처럼 **끝나지 않는 루프**는 상태 전환이 아니므로
이 세 토큰의 대상이 아닙니다.

이 세 값은 **관행에서 가져온 것**이고 실측 근거가 없습니다 — 시스템에서 유일합니다.
`prefers-reduced-motion`에서는 전환과 루프를 모두 끕니다.
