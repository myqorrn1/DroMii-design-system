# 제품별 설정과 확장

## 기본 구조

각 솔루션은 DroMii Core를 복사해 따로 수정하지 않습니다.

```text
DroMii Core
├── K-AQUAS 설정 + 수질 업무 확장
├── D-ROAD 설정 + 도로 조사 확장
└── D-FIND 설정 + 업무 확장
```

Core는 구조, 상태, 상호작용과 접근성을 소유합니다. 솔루션은 브랜드 표현과 업무 데이터를
주입하고, Core로 설명할 수 없는 업무 컴포넌트만 추가합니다.

## 제품에서 바꿀 수 있는 것

- 기준색을 역할 토큰에 연결하는 방식
- 라이트·다크 기본 설정
- 지도처럼 정보량이 높은 화면의 compact 밀도
- 제품명, 메뉴 내용, 화면 제목과 업무 문구
- 수질·도로·탐지 등 도메인 아이콘과 데이터 시각화
- 실제 업무에 필요한 전용 패널과 필드

## Core에서 유지하는 것

- 글자 위계와 기본 폰트
- 간격 단계와 radius 체계
- 버튼의 중요도와 상태 의미
- 입력 라벨, 도움말, 오류 위치
- 표, 폼, 알림, 메뉴의 기본 구조
- 키보드 포커스와 접근 가능한 이름
- 상태를 색만으로 전달하지 않는 규칙
- 토큰 명명과 변경 절차

## 현재 제품 설정

### K-AQUAS

- 기준색 `#5098EC` 유지
- 라이트 화면을 현재 기본으로 사용
- 지도 도구에는 compact 밀도 사용 가능
- MUI 기본 파랑과 Bootstrap 파랑은 브랜드 역할로 사용하지 않음

### D-ROAD

- 기존 보라 기준색 계열 유지
- `#272934` 중심 다크 표면을 현재 기본 후보로 사용
- 서버 소스의 Vite 기본색과 임시 밝은 관리자 화면은 제품 기준으로 간주하지 않음
- 메뉴별 임의 색과 이모지는 Core 아이콘과 선택 상태로 교체

### D-FIND

- 프론트 코드 감사 전
- 기준색과 업무 구조를 확인한 뒤 동일한 Core 역할에 연결
- 기존 두 제품과 다르다는 이유만으로 Core를 복제하지 않음

## 확장 판단 순서

1. 기존 Core 컴포넌트의 조합으로 해결 가능한지 확인합니다.
2. 속성이나 슬롯 추가로 두 제품이 함께 사용할 수 있는지 확인합니다.
3. 특정 업무에만 필요한 경우 제품 확장으로 둡니다.
4. 다른 제품에서도 반복되면 Core 승격을 검토합니다.
5. 제품 확장이 Core의 접근성과 상태 규칙을 바꾸지는 못합니다.

로고 분석과 로고 체계 변경은 현재 프로젝트 범위에서 제외합니다.
