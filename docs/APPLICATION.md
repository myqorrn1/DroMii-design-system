# 제품 적용 가이드

이 문서는 디자인 확정 뒤 K-AQUAS, D-ROAD, D-FIND에 적용할 때 사용하는 절차입니다.
현재 제품 적용은 보류하며, v0.15 CSS와 HTML은 기준 검토용입니다.

## 적용 전에 확인할 것

- [현재 상태](STATUS.md)의 디자인 완료 체크리스트가 통과했는지 확인합니다.
- 적용할 제품의 프론트 기술 스택과 빌드 방식을 확인합니다.
- 신규 화면인지 기존 화면 전환인지 구분합니다.
- 제품 설정과 필요한 업무 확장을 [제품별 설정](THEMING.md)에 기록합니다.
- 운영 또는 스테이징 주소와 테스트 계정을 준비합니다.

## 적용 순서

### 1. 토큰 연결

토큰 패키지 또는 생성된 CSS를 앱의 최상위에서 한 번 불러옵니다.

```html
<link rel="stylesheet" href="fonts.css">
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="components/base.css">
```

현재 HTML 기준은 다음처럼 제품을 선택합니다.

```html
<body data-product="k-aquas">
```

최종 패키지에서는 `brand`, `scheme`, `density`를 각각 설정할 수 있게 바꿉니다.

### 2. 앱 셸부터 적용

신규 화면은 개별 버튼보다 AppShell, Header, Sidebar, Content 구조를 먼저 적용합니다.
그래야 화면마다 다른 여백과 메뉴 구조가 다시 생기지 않습니다.

### 3. 공용 컴포넌트로 화면 조립

Button, Input, Table 같은 요소를 제품에서 다시 스타일링하지 않습니다. Core props와
토큰으로 표현할 수 없는 요구는 제품 CSS를 덧붙이기 전에 확장 판단 절차를 거칩니다.

### 4. 업무 확장 추가

수질 지표, 도로 탐지 범례, 지도 도구처럼 특정 제품에만 필요한 요소는 제품 확장으로 둡니다.
색, 포커스, 오류와 비활성 상태는 Core 규칙을 그대로 사용합니다.

### 5. 대표 흐름 검증

정상 상태만 확인하지 않습니다.

- 로딩과 데이터 없음
- 입력 오류와 서버 오류
- 권한 없음과 읽기 전용
- 긴 이름과 많은 데이터
- 키보드 사용과 200% 확대
- 1024·1200·1440·1920px

### 6. 신규 화면부터 배포

첫 적용은 신규 화면에서 시작합니다. 이후 수정 빈도가 높은 기존 화면을 작은 단위로 전환하고,
전환 전후의 기능과 접근성을 확인합니다.

## 기존 화면 전환 원칙

- 화면 전체를 한 번에 다시 만들 필요는 없습니다.
- 전역 토큰, 앱 셸, 기본 입력, 알림, 표 순서로 영향 범위를 넓힙니다.
- 기존 서버 API와 데이터 모델은 디자인 변경의 대상이 아닙니다.
- 임시 호환 CSS에는 제거 조건과 대상 화면을 기록합니다.
- 제품별 복사본 대신 Core 수정 또는 공식 확장으로 해결합니다.

## 적용 PR에 남길 내용

- 적용한 Core 버전
- 교체한 기존 요소와 화면
- 제품 확장 또는 예외
- 키보드·대비·화면 폭 검증 결과
- 되돌리는 방법
- 남은 마이그레이션 범위

## 현재 구현 형태의 한계

v0.15의 `components/base.css`는 디자인 검토와 빠른 프로토타입에 사용할 수 있지만,
컴포넌트 동작과 접근성을 자동으로 제공하지 않습니다. 실제 제품 적용 전 React 공용 패키지로
구현해 다이얼로그 포커스, 탭 이동, 알림 영역, 업로드 진행과 같은 동작을 포함해야 합니다.
