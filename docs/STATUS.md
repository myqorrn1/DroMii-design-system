# 현재 상태

> 2026-09-28 기준 · v0.17 업무 패턴 검토본 · **DroMii Core 디자인 미완료**

## 현재 결론

K-AQUAS와 D-ROAD의 기존 디자인에서 공통 구조를 추출한 토큰·HTML/CSS 견본·사용 기준이
있다. D-ROAD 운영 폴더의 React 소스와 로컬 K-AQUAS 소스를 다시 감사했고,
본문 크기·밀도, 다크 기본값, 좁은 패널 제어 높이는 소유자가 승인한 선택으로
토큰에 반영하고 단계 4 방향을 승인했다. 목록·확인·업로드·지도 업무 패턴의 가상 상태
견본과 사용 기준도 만들었다. **브라우저 시각 검증과 실제 제품 동작 대조는 아직 남았다.** 제품별 세부
매핑은 실제 적용 계획에서 다룬다. 현재 견본을 바로 제품에
적용하는 React 패키지는 없다. 대표 화면은 소유자가 원하지 않아 제거했으며 이번 범위에서
다시 만들지 않는다.

판단 순서는 [`작업 인계`](HANDOFF.md), KRDS의 채택과 예외는
[`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에만 기록한다.

## 현재 시각 견본

- 211개 고유 CSS 토큰, 3계층·3축의 제품별 역할 색·표면·글자·간격 후보
- 두 제품의 이전 Core 13px·새 기본 16px·제한된 compact 14px 비교 견본
- 버튼, 입력, 선택, 배지·칩, 기본 표·페이지 이동·빈 상태, 알림 3종
- 앱 셸·헤더·메뉴, 폼 섹션·저장 상태, 탭·툴팁
- 선택형 로그의 **가상 데이터** 검색, 현재 표시 항목 선택, 삭제 확인·취소·결과
- 네 업무 패턴의 정상·빈 상태·오류·권한 제한·로딩과 가능한 부분 성공의 가상 견본
- 헤더·메뉴의 현재 위치, 그룹 제목, 알림·계정 펼침 영역을 정돈한 시각 견본
- 데이터 표의 결과 건수와 기본·조밀 밀도를 전환해 볼 수 있는 견본
- 알림 3종의 Core 표현과 토스트·다이얼로그 로컬 동작, 기본 폼의 변경·저장 상태 견본
- 버튼·입력·배지 견본의 공통 서체·문서 배치와 제품 표현 전환, 처리 중·오류·선택 상태
- 탭·툴팁의 읽기 위계와 가상 페이지 이동의 현재 위치·이전/다음 상태
- 업무 패턴의 상태별 알림 위계, 단일·다중 파일 경계, 가상 지도 레이어 선택 표현
- 긴 파일명·다중 선택 목록과 좁은 폭 배너·검색 입력의 재배치 규칙

이 견본들은 확정된 컴포넌트 패키지가 아니다. `components/table-selection.html`은
**현행 D-ROAD UI가 아닌 미사용 일괄 삭제 API 기반 후보**이며 로컬 가상 목록만 바꾼다.
K-AQUAS·D-ROAD의 항목별 부분 성공은 확인되지 않았고, 권한·재시도 범위는 실제 API에서
검증해야 한다. `components/workflows.html`의 상태 전환도 로컬 견본이다.

## 검증한 것과 검증하지 않은 것

- `npm run check`는 토큰 동기화, 참조·링크·라벨·매직 넘버 역할 대비 오류를 검사한다.
- 1024·1200·1440·1920px에서는 기존 폼·메뉴·표의 가로 넘침을 확인했다.
- 320px·512px **유효 화면 폭**에서 앱 셸은 세로 재배치되고 표는 내부 가로 스크롤된다.
- 본문 건너뛰기의 Tab·Enter 초점 이동과 가상 로그의 검색·선택·취소·삭제 흐름을
  브라우저에서 확인했다.
- 단계 3 문서·개요 문구 변경은 `npm run check`와 `git diff --check`를 통과했다.
  로컬 `file://` 브라우저 확인은 URL 보안 정책으로 차단돼 이번 변경에서는 수행하지 못했다.
- 단계 4의 `npm run check`는 토큰 경로 300개·고유 CSS 변수 211개·HTML 19개와
  네 가지 브랜드×명도 조합의 지정 대비를 통과했다. 이전 Core와 비교한 두 제품 기본
  조합의 색상 역할값은 각각 66개 모두 같다. `git diff --check`도 통과했다.
  단계 4 비교 견본의 실제 브라우저 시각·확대 검증은 아직 완료하지 못했다.
- 단계 5의 `npm run check`는 토큰 경로 300개·고유 CSS 변수 211개·HTML 20개를
  검사했다. `git diff --check`도 통과했다. 새 견본의 브라우저 시각·키보드 검증은
  같은 로컬 URL 보안 정책 때문에 완료하지 못했다.
- 헤더·메뉴 디자인 후속 작업에서 토큰 값과 제품 메뉴를 유지하고 현재 위치·그룹·
  펼침 영역의 위계를 다듬었다. 표에는 결과 건수와 밀도 전환을 추가했다.
  정적 검사는 통과했으며 새 배치의 브라우저 검증은 남았다.
- 알림 견본의 별도 서체·오래된 사례를 걷어내고 Core 토큰 표현으로 통일했다.
  폼의 로컬 변경·취소·저장 상태를 연결했다. 실제 저장·삭제 요청은 하지 않으며,
  시각·키보드·확대 검증은 아직 남았다.
- 버튼·입력·배지 견본의 서체·문서 배치를 공통화하고 제품 전환을 연결했다. 칩 선택은
  가상 상태만 바꾸며, 처리 중 버튼을 중복 실행할 수 없게 했다. 정적 검사는 통과했지만
  새 견본의 실제 브라우저 시각·키보드 검증은 남았다.
- 화면 안 탐색 견본에서 탭 패널·툴팁 설명·페이지 위치를 정리하고 페이지 번호를
  로컬로 전환하게 했다. 정적 검사는 통과했으며 실제 브라우저 검증은 남았다.
- 업무 패턴 견본에서 상태 알림·파일 입력·제품별 부분 성공 경계·지도 레이어 표현을
  수정했다. 정적 검사는 통과했으며 실제 브라우저 시각·키보드 검증은 남았다.
- 긴 파일 선택 결과를 개수와 별도 목록으로 분리하고 좁은 폭의 배너·검색 입력을
  재배치했다. 정적 검사를 통과해도 실제 화면 확대·긴 파일명 검증은 별도로 남는다.
- **실제 브라우저 200% 확대**, 모든 컴포넌트의 키보드·스크린리더, 두 제품의
  운영 로그인 후 흐름은 검증하지 않았다. 유효 화면 폭 검사는 확대율 시험이 아니다.

## 감사 이후 결정과 후속 검토

- **승인된 파운데이션:** 본문 기본 16px·표/지도 compact 14px, D-ROAD 다크 기본값
  유지·고대비 자리 예약, 일반 문자 제어 40/44px·좁은 패널 compact 32px·24px
  아이콘 전용. KRDS와 다른 결정은 [예외 목록](PUBLIC_SECTOR_DIRECTION.md)에 기록했다.
- **후속 적용 계획:** [제품 소스 재감사](../context/06-product-audit-2026-09-23.md)의
  색·간격·radius·구조·MUI 근거를 화면별 Core 요소와 매핑한다. K-AQUAS z-index
  테마, 현재 1열 폼과 실제 제품의 열·순서도 그때 확인한다.
- **9월 28일 후속 소스 대조:** [업무 패턴 실측](../context/06-product-audit-2026-09-23.md#2026-09-28-업무-패턴-대조--읽기-전용-후속-확인)에서
  D-ROAD 로그 일괄 삭제 API는 미사용, D-ROAD 업로드는 TIFF 한 파일 뒤 AI 분석 자동
  시작, K-AQUAS 업로드는 여러 파일을 한 요청에 포함함을 확인했다. 두 제품에 파일별
  부분 성공·수치 진행률 근거는 없어 조건부 후보로 남겼다.
- **제품 적용:** 선택형 로그 삭제의 도입 여부·권한·감사 보존과 사용자 목록 검색·페이지
  동작을 실제 업무 흐름에서 확인한다.
