# 현재 상태

> 2026-09-29 기준 · v0.18 DroMii Core 파운데이션·공용 컴포넌트 설계 구현 · 소유자 최종 승인 전

## 현재 결론

K-AQUAS와 D-ROAD의 실제 프런트 코드에서 추출한 공통 형태를 토큰, 공용 CSS,
브라우저 견본과 사용 기준으로 정리했다. 기준색·제공 로고·제품 메뉴와 D-ROAD 다크
기본값을 보존하고 접근성·상태 표현·좁은 폭·긴 내용의 불일치를 리팩토링했다.
KRDS는 [선택한 점검 항목](PUBLIC_SECTOR_DIRECTION.md)에만 사용한다. 고대비 명도는
토큰 구조에 자리만 있으며 아직 선택 가능한 테마가 아니다.

파운데이션과 [공용 컴포넌트 목록](COMPONENTS.md)의 디자인 견본을 구현했다. 다만
**앱 셸·헤더·메뉴는 지도가 주 콘텐츠라는 소유자 피드백에 따라 지도형·관리형
견본으로 재구성했고, 소유자 검토 전**이다. 기존 248px 고정 메뉴와 안쪽 여백을
지도 업무에 사용하지 않는다.
제품에 적용된 React 패키지, 실제 API 검증 또는 소유자 최종 승인을 뜻하지 않으며,
대표 화면은 만들지 않는다. 제품별 매핑·적용은 [적용 가이드](APPLICATION.md)의
후속 범위다.

## 결과물

- `tokens/source.json` → 생성 `tokens.css`: reference / semantic / component 3계층,
  brand / scheme / density 3축. 기본 본문 16px, 표·지도 패널 compact 14px.
- `components/base.css`: 버튼·입력·선택·배지, 알림·확인, 표·정렬·페이지 이동,
  앱 셸·헤더·메뉴, 폼, 탭·툴팁, 경로·드롭다운·펼침, 진행률·로딩의 공용 스타일.
- `foundations/`와 `components/`: 두 제품 표현, 상태, 긴 내용과 좁은 유효 폭을
  직접 살펴보는 HTML 견본. 차트는 색과 함께 범주·숫자를 표시한다.
- `docs/`: 토큰·컴포넌트·접근성·업무 패턴·제품별 확장 경계의 사용 기준.
  [제품 소스 감사](../context/06-product-audit-2026-09-23.md)가 근거다.
- 업무 패턴은 목록·검색, 위험 동작 확인, 업로드, 지도 주변 제어의 정상·빈 상태·
  오류·권한 제한·로딩을 다룬다. 부분 성공과 수치 진행률은 제품 API가 제공할 때만 쓴다.

## 검증

- `npm run check`: 토큰 생성 동기화·참조·링크·라벨·지정한 색 대비를 검사한다.
  마지막 검사 기준 토큰 경로 300개, 고유 변수 211개, HTML 20개가 통과했다.
- 공개 GitHub Pages에서 K-AQUAS 라이트와 D-ROAD 다크의 차트·입력·표·앱 셸·
  업로드 로딩을 시각 확인했다. 표 정렬은 행 순서와 `aria-sort`가 함께 바뀐다.
- 512px 유효 폭에서 표는 내부만 가로 스크롤하고, 512px·320px에서 앱 셸은
  재배치되며 문서 전체 가로 넘침이 없었다. 이는 실제 브라우저 200% 확대 시험과 다르다.
- 브라우저 캐시 때문에 이전 CSS가 보인 문제를 CSS URL 버전으로 해결했다.
  최신 Pages에서 320px 유효 폭의 드롭다운 전체 표시·키보드 선택·Esc 초점 복귀,
  긴 버튼 문구의 높이 확장, 읽기 전용 입력의 두 제품 표현도 확인했다.
- 파운데이션 전후 비교에서 2열 예시 표가 실제 업무 표의 700px 최소 폭을 상속해
  카드 밖으로 돌출되는 문제를 확인했다. 비교 견본에만 폭 예외를 두고 로컬 319px·
  1280px 유효 폭에서 여섯 카드의 입력·표와 문서 전체 가로 넘침을 다시 확인했다.
- [D-ROAD 운영 셸](../context/06-product-audit-2026-09-23.md#2026-09-29-d-road-운영-셸-시각-확인--읽기-전용)을
  로그인 후 읽기 전용으로 확인했다. 헤더는 1280px에서 약 38px, 1920px에서 약 58px,
  좌측 패널은 각각 250px·326px이며 지도 아래 결과 줄이 따로 있다.
- [K-AQUAS 운영 셸](../context/06-product-audit-2026-09-23.md#2026-09-29-k-aquas-운영-셸-시각-확인--읽기-전용)은
  인증된 브라우저에서 읽기 전용으로 확인했다. 지도는 51px 기능 레일과 280px 작업
  패널을 쓰고 고정 가로 헤더가 없다. 관리 화면은 240px 메뉴와 60px 제목 영역이다.
  [핵심 업무 후속 확인](../context/06-product-audit-2026-09-23.md#2026-09-29-핵심-업무-화면-후속-확인--읽기-전용)에서
  두 제품의 기능 전환·업로드 대화상자·사용자 관리 구조를 대조했다.
- 로컬 브라우저에서 새 지도형 셸의 K-AQUAS 라이트·D-ROAD 다크, 패널 접힘 시
  지도 확장과 키보드 복귀를 확인했다. 512px·320px 유효 폭에서 페이지 가로 넘침이
  없고 좁은 폭에서는 작업 패널이 지도 위에 겹친다. 실제 운영 화면의 오류·권한
  제한 상태나 서버에 파일을 보내는 동작은 검증하지 않았다.

## 남은 확인과 적용

1. 지도형·관리형 셸 견본을 소유자와 검토해 패널 폭과 제품별 배치를 결정한다.
2. 실제 200% 확대, 전체 키보드 경로, 스크린리더, 운영 제품의 대표 업무 흐름은
   확인하지 않았다. 소유자 최종 디자인 승인 전 품질 확인으로 남긴다.
3. 서버 응답·권한·삭제 정책·실제 업로드 결과는 제품 연동 때 검증한다. D-ROAD
   일괄 삭제 API는 현재 화면에서 쓰이지 않으며, 파일별 부분 성공·수치 진행률은
   두 제품에서 확인된 동작이 아니다.
4. D-FIND 브랜드는 제품 소스 감사 후 확장한다. 고대비 테마와 Combobox는
   사용 근거·별도 결정이 있을 때 설계한다. 제품 코드 변경은 이번 범위 밖이다.

현재 디자인의 포함·제외 경계는 [컴포넌트 목록](COMPONENTS.md), 다른 도구의 이어받기
절차는 [작업 인계](HANDOFF.md)에 기록한다.
