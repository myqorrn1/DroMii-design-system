# 0001. 코드 중심으로 디자인시스템을 관리한다

- 상태: 승인
- 결정일: 2026-09-10

## 배경

기존 디자인시스템은 정적 HTML과 CSS로 제작돼 직원이 브라우저에서 시각적으로 확인할
수 있다. 별도의 Figma 파일이나 Storybook을 운영하면 실제 제품 코드와 문서 사이에 또
하나의 관리 대상이 생긴다.

## 결정

드로미 디자인시스템은 Git 저장소의 토큰, 컴포넌트와 문서를 원본으로 관리한다.

- Figma를 필수 원본으로 사용하지 않는다.
- Storybook을 필수 도구로 사용하지 않는다.
- 현재 HTML 문서 사이트를 발전시켜 사내 포털로 사용한다.
- 문서 사이트의 견본은 제품에 배포하는 실제 컴포넌트를 사용한다.
- 반복되는 토큰 표, 상태 목록, 메뉴와 버전은 코드에서 자동 생성한다.
- GitHub의 변경 이력, 검토와 자동 배포를 운영 절차로 사용한다.

## 결과

직원은 브라우저에서 디자인 기준을 확인하고, 개발자는 같은 페이지에서 실제 구현과
사용법을 확인할 수 있다. 별도의 디자인 도구와 코드 사이를 수동으로 동기화할 필요가
없어진다.

대신 문서 사이트가 직접 제공해야 하는 기능이 생긴다. 테마와 상태 전환, 접근성 검사,
시각 회귀 검사와 자동 배포가 이에 해당한다. 이 기능은 필요한 범위부터 순차적으로
구축한다.

## 재검토 조건

컴포넌트 수와 참여자가 늘어 자체 문서 사이트 유지 비용이 커지거나, 제품팀이 독립적인
컴포넌트 개발 환경을 필요로 할 때 Storybook 또는 다른 도구 도입을 다시 검토한다.
