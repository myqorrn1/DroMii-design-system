# 접근성 기준

DroMii Core는 WCAG 2.2 AA를 기본 기준으로 합니다. 접근성은 제품별 선택 사항이 아니라
Core 컴포넌트의 완료 조건입니다.

## 현재 자동 검사

`npm run check`는 다음을 확인합니다.

- 토큰 JSON과 생성 CSS의 동기화
- 없는 토큰 참조와 별칭 순환
- HTML의 중복 ID
- `label`과 입력 요소 연결
- 로컬 링크와 자산 경로
- 주요 버튼, 텍스트, 플레이스홀더 색상 대비

자동 검사는 기본 오류만 잡습니다. 키보드 흐름과 스크린리더 문맥은 별도로 검토합니다.

## 키보드

- 모든 동작은 Tab으로 도달할 수 있어야 합니다.
- 포커스 표시를 제거하지 않습니다.
- 탭은 좌우 방향키, Home, End를 지원합니다.
- 다이얼로그가 열리면 포커스를 안으로 옮기고 닫히면 실행 버튼으로 돌려보냅니다.
- 메뉴, 콤보박스, 날짜 선택기는 WAI-ARIA 키보드 패턴을 따릅니다.
- 지도 자체 조작과 지도 위 버튼을 분리해 접근할 수 있어야 합니다.

## 색과 상태

- 일반 텍스트는 최소 4.5:1 대비를 유지합니다.
- 큰 텍스트는 최소 3:1 대비를 유지합니다.
- 포커스와 UI 경계는 주변 색과 최소 3:1을 목표로 합니다.
- 성공·경고·오류는 색과 함께 아이콘 또는 명시적인 문구를 제공합니다.
- 차트와 지도 범례는 색 외에 라벨, 순서, 모양을 함께 사용합니다.

## 입력과 오류

- 플레이스홀더로 라벨을 대신하지 않습니다.
- 필수 여부는 글자와 프로그램 속성으로 함께 전달합니다.
- 오류 문구는 문제가 있는 입력 바로 아래에 둡니다.
- `aria-invalid`와 `aria-describedby`로 입력과 오류를 연결합니다.
- 저장 실패 시 화면 상단 알림과 해당 필드 오류를 함께 사용할 수 있습니다.

## 알림과 다이얼로그

- 토스트는 완료된 결과처럼 놓쳐도 업무를 계속할 수 있는 정보에 사용합니다.
- 배너는 조건이 유지되는 동안 계속 보여야 하는 정보에 사용합니다.
- 다이얼로그는 사용자의 답이 있어야 다음으로 갈 수 있을 때 사용합니다.
- 긴 오류나 실패는 자동으로 사라지는 토스트만 사용하지 않습니다.

## 크기와 모션

- 누르는 대상은 최소 24×24px을 확보합니다.
- 지도 위 조밀한 아이콘 버튼도 24px보다 작게 만들지 않습니다.
- `prefers-reduced-motion`에서는 상태 이해에 필요하지 않은 모션을 제거합니다.
- 로딩 애니메이션이 멈춰도 상태 문구가 남아야 합니다.

## 디자인 확정 전 수동 검사

- [ ] Tab 순서가 화면의 읽기 순서와 같다.
- [ ] 포커스가 가려지거나 사라지는 곳이 없다.
- [ ] 200% 확대에서 주요 작업이 가능하다.
- [ ] 키보드만으로 폼, 표, 다이얼로그, 메뉴를 사용할 수 있다.
- [ ] 오류, 빈 상태, 로딩 상태를 스크린리더가 이해할 수 있다.
- [ ] 색각 차이가 있어도 차트와 지도 상태를 구분할 수 있다.
