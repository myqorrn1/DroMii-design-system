# 접근성 기준

DroMii Core는 KWCAG 2.2 준수를 전제로 접근성을 설계하고 검증합니다. WCAG 2.2 AA도
내부 점검에 사용합니다. 접근성은 제품별 선택 사항이 아니라 Core 컴포넌트의 완료
조건입니다. 채택 범위와 현재 검증 수준은
[`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에 기록합니다.

## 현재 자동 검사

`npm run check`는 다음을 확인합니다.

- 토큰 JSON과 생성 CSS의 동기화
- 없는 토큰 참조와 별칭 순환
- HTML의 중복 ID
- `label`과 입력 요소 연결
- 로컬 링크와 자산 경로
- 매직 넘버 40/50/70/90 등급으로 지정한 버튼·상태·본문·포커스 색 조합의 대비

자동 검사는 기본 오류만 잡습니다. 키보드 흐름과 스크린리더 문맥은 별도로 검토합니다.

## 키보드

- 모든 동작은 Tab으로 도달할 수 있어야 합니다.
- 헤더와 반복 메뉴 앞에 본문 건너뛰기를 두고 대상에 포커스가 이동해야 합니다.
- 포커스 표시를 제거하지 않습니다.
- 탭은 좌우 방향키, Home, End를 지원합니다.
- 다이얼로그가 열리면 포커스를 안으로 옮기고 닫히면 실행 버튼으로 돌려보냅니다.
- 가로 스크롤 표는 키보드로 초점을 받을 수 있고, 보이지 않는 열로 이동할 수 있어야 합니다.
- 목록 선택과 검색 결과가 바뀌면 건수와 작업 결과를 텍스트로 알립니다.
- 펼침 메뉴는 요약 버튼에서 열고 Tab으로 항목을 이동하며 Esc로 닫습니다. 날짜는
  브라우저 기본 입력을 사용합니다. Combobox는 제품 요구가 확인될 때 별도 설계합니다.
- 지도 자체 조작과 지도 위 버튼을 분리해 접근할 수 있어야 합니다.

## 색과 상태

- 일반 텍스트는 최소 4.5:1 대비를 유지합니다.
- 큰 텍스트는 최소 3:1 대비를 유지합니다.
- 포커스와 UI 경계는 주변 색과 최소 3:1을 목표로 합니다.
- 성공·경고·오류는 색과 함께 아이콘 또는 명시적인 문구를 제공합니다.
- 차트와 지도 범례는 색 외에 라벨, 순서, 모양을 함께 사용합니다.
- 읽기용 본문은 기본 16px·행간 150% 이상을 사용합니다. 표·지도 패널의 compact 14px
  예외 범위와 근거는 [`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에 기록합니다.

## 입력과 오류

- 플레이스홀더로 라벨을 대신하지 않습니다.
- 필수 여부는 글자와 프로그램 속성으로 함께 전달합니다.
- 오류 문구는 문제가 있는 입력 바로 아래에 둡니다.
- `aria-invalid`와 `aria-describedby`로 입력과 오류를 연결합니다.
- 저장 실패 시 화면 상단 알림과 해당 필드 오류를 함께 사용할 수 있습니다.

## 알림과 다이얼로그

- 토스트는 완료된 결과처럼 놓쳐도 업무를 계속할 수 있는 정보에 사용합니다.
- 배너는 조건이 유지되는 동안 계속 보여야 하는 정보에 사용합니다.
- 다이얼로그는 사용자의 답이 있어야 다음으로 갈 수 있을 때 사용합니다.
- 긴 오류나 실패는 자동으로 사라지는 토스트만 사용하지 않습니다.

## 크기와 모션

- 누르는 대상은 최소 24×24px을 확보합니다.
- 지도 위 조밀한 아이콘 버튼도 24px보다 작게 만들지 않습니다.
- `prefers-reduced-motion`에서는 상태 이해에 필요하지 않은 모션을 제거합니다.
- 로딩 애니메이션이 멈춰도 상태 문구가 남아야 합니다.

## 디자인 확정 전 수동 검사

- [ ] Tab 순서가 화면의 읽기 순서와 같다.
- [ ] 포커스가 가려지거나 사라지는 곳이 없다.
- [x] 200% 확대에서 검토한 Core 견본의 주요 작업이 가능하다.
- [ ] 키보드만으로 폼, 표, 다이얼로그, 메뉴를 사용할 수 있다.
- [ ] 오류, 빈 상태, 로딩 상태를 스크린리더가 이해할 수 있다.
- [ ] 색각 차이가 있어도 차트와 지도 상태를 구분할 수 있다.

### 2026-09-29 브라우저 확인 범위

- D-FIND 제품 표현 견본을 Chrome 실제 200%(640×299 CSS 유효 화면)에서 확인했다.
  문서 가로 넘침과 버튼·입력의 화면 밖 돌출은 없었고, 표는 내부에서만 가로 스크롤됐다.
  필터의 선택 상태가 `aria-pressed`와 상태 문구에 함께 반영됐다. 이는 D-FIND 운영
  제품 화면이나 실제 스크린리더 발화 검증은 아니다.
- Chrome 실제 200% 확대(640×299 CSS 유효 화면)에서 대표 화면을 제외한 파운데이션·
  컴포넌트·업무 패턴 견본 17개의 문서 전체 가로 넘침이 없었다. 전후 비교의 여섯
  카드에서도 입력과 표가 카드 안에 남았다. 모든 하위 상태와
  도메인 화면까지 통과했다는 뜻은 아니다.
- 긴 폼 다이얼로그는 K-AQUAS 라이트·D-ROAD 다크의 1280×600 견본과 Chrome 200%에서
  제목·하단 버튼이 보이고 입력 영역만 스크롤됐다. Tab으로 모든 입력과 취소 버튼에
  도달했고, Esc로 닫으면 시작 버튼에 초점이 돌아왔다.
- 200%에서 탭 방향키·End, 페이지 이동, 펼침 메뉴, 표 내부 가로 스크롤·정렬,
  폼의 `aria-invalid`·오류 연결·저장 실패 알림, 목록 오류와 지도 레이어 상태를
  키보드와 브라우저 접근성 트리로 확인했다. 견본 전체의 대화형 요소 이름을 검사해
  간격 견본의 누락 레이블 한 곳을 고쳤다.
- **실제 스크린리더 음성 발화와 전체 Tab 경로는 아직 검증하지 못했다.** 접근성 트리의
  역할·이름·상태 확인은 음성 사용성 검사를 대체하지 않는다. 제품 적용 전 VoiceOver와
  Windows NVDA에서 오류·로딩 발표, 다이얼로그 초점, 표·지도 대체 정보를 확인한다.

### 2026-10-02 테마 상속 검수

HTML·React 제품/명도/밀도의 토큰 계산값과 버튼·입력·표를 확인했다. 범위와
미검증 항목은 [현재 상태](STATUS.md)를, 당시 상세 기록은 [2026-10 원문](history/2026-10.md)을 따른다.
K-AQUAS 흰 글자 안은 소유자가 승인해 공용 토큰에 반영했다. 기본·hover·pressed
대비는 4.76:1·7.31:1·9.80:1이며, 밝은 기준 파랑 위 흰 글자는 사용하지 않는다.
일반 텍스트의 4.5:1 기준은
[WCAG 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 따른다.
