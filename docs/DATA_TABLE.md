# 데이터 테이블 — Core 1차 기준

시각 견본: [기본 표](../components/table.html),
[선택형 로그 표](../components/table-selection.html).
서버 실패·부분 성공·권한 제한은 [업무 패턴](PATTERNS.md#1-목록검색)의 목록 계약을 따른다.

## 기본형

- 열 이름은 짧고 구체적으로 쓴다. 각 행의 값은 열 이름만으로 이해할 수 있어야 한다.
- 이름·날짜·상태 등 텍스트는 왼쪽, 비교할 수치값은 오른쪽에 정렬한다. 날짜는 연도를
  포함해 같은 형식으로 표시한다.
- 행 전체를 클릭 대상으로 만들지 않는다. 상세 보기나 수정은 행 안의 명시적인 링크·버튼으로
  제공하고, 반복 버튼에는 대상 이름을 접근 가능한 이름에 포함한다.
- 페이지 이동은 현재 페이지를 문자와 `aria-current="page"`로 표시한다. 비활성 이전·다음
  버튼은 실제 범위에 맞춰 갱신한다.
- 데이터가 전혀 없는 상태와 검색 결과가 없는 상태를 구분하고, 각각 다음 행동을 제시한다.
- 기본 밀도에서 읽기와 행 조작을 우선한다. 조밀한 표가 필요한 업무 영역에서만
  `compact`를 선택하며, 견본의 밀도 전환으로 두 행 높이와 글자 위계를 비교한다.
- 정렬 가능한 열만 머리글 안에 버튼을 넣는다. 방향은 머리글의 `aria-sort`와 화살표를
  함께 갱신한다. 서버 정렬이라면 응답이 완료되기 전 현재 결과의 정렬을 바꾼 것처럼
  표시하지 않는다. 높이 제한이 필요한 목록은 `tbl-wrap--scroll`에서 머리글을 고정한다.

## 선택형 목록의 경계

사용자 관리 견본에는 실제 일괄 작업이 없으므로 선택 열을 두지 않는다. D-ROAD에는
접속 로그 일괄 삭제 API 함수가 정의돼 있지만 현재 로그 화면에서 쓰이지 않는다. 따라서
[선택형 로그 표](../components/table-selection.html)는 **조건부 후보**이고 기존 서비스의
동작을 재현한 것이 아니다. 일괄 작업이 실제로 승인되면 체크박스·선택 건수·수행할 작업·
확인 단계와 결과를 한 패턴으로 둔다. 전체 선택의 범위는 현재 페이지 또는 현재 표시된
결과처럼 구체적으로 알린다. 이 견본은 가상 데이터의 로컬 동작만 제공한다. 로그 보존·
권한·항목별 결과 계약은 확인되지 않았다.

검색 조건이 바뀌면 선택을 초기화한다. 일부 행만 선택되면 전체 선택 체크박스는 혼합 상태로
표시하고, 선택이 0건이면 일괄 작업 영역을 숨긴다. 삭제처럼 되돌릴 수 없는 동작은 대상
건수를 보여주는 확인 다이얼로그에서 실행한다. 취소 시 선택과 초점을 유지하고, 실행 결과는
목록 가까이에 알린다. 세부 검색 규칙은 [`목록 검색·필터`](LIST_FILTER.md)를 따른다.

좁은 유효 화면에서는 표 자체를 줄여 글자를 세로로 쪼개지 않고 가로 스크롤한다. 스크롤
영역을 키보드로 찾을 수 있게 이름과 초점을 제공한다. 검색·정렬·페이지네이션의 서버
동작은 각 제품의 API와 맞춰야 한다.

## KRDS 점검 항목

[KRDS 테이블](https://www.krds.go.kr/html/site/component/component_04_11.html)의
열 최소화, 데이터 유형별 정렬, 명시적 조작 요소를 **제품 근거 뒤의 점검 항목**으로
사용한다. 전문 업무에서 고정 열·가로 스크롤·높은 밀도가 필요하면 읽기 순서, 헤더 연결,
키보드 이동을 함께 검증한다. 적용 경계는
[`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에 둔다.

## 남은 검증

- 실제 브라우저 200%에서 견본 표의 내부 가로 스크롤과 키보드 이동은 확인했다.
  고정 헤더·열의 모든 제품 데이터 조합은 아직 검증하지 않았다.
- 긴 이름, 빈 값, 단위가 있는 수치, 오류·권한 제한 행의 표시
- D-ROAD 선택 삭제의 도입 여부·권한·실패·감사 보존과 K-AQUAS 관리 목록의 조작 방식 교차 검증
