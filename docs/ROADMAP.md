# 구축 로드맵

각 단계는 문서만 완성하는 것으로 끝내지 않고, 다음 단계에서 사용할 수 있는 코드와
검증 결과를 남긴다. 실제 제품 근거가 필요한 결정은 해당 코드에 접근한 뒤 확정한다.

## 0. 기준선 정리

- [x] v0.12 파일과 문서의 불일치 목록 확정
- [x] 폐기된 기능이 규칙과 프롬프트에 남은 부분 정리
- [x] 접근성 예외 재검토
- [x] 프로젝트 목표, 범위, 변경 절차 고정

완료 조건: 같은 항목을 서로 다르게 설명하는 문서가 없고, 이후 변경의 판단 기준이
한 곳에 모여 있다.

상태: **완료 (v0.13, 2026-09-10)**

## 1. 토큰 원본 구축

- [ ] 기존 CSS 토큰을 reference, semantic, component 계층으로 분류
- [ ] 제품, 명도, 밀도를 독립된 축으로 설계
- [x] 표준 JSON 원본에서 CSS 변수를 생성
- [x] 미정의 참조, 순환 참조, 대비와 중복을 자동 검사

완료 조건: 사람이 토큰 JSON만 수정하면 CSS와 문서가 함께 갱신된다.

## 2. 사내 문서 사이트 재구성

- [x] 현재 HTML의 정보 구조와 시각 자산을 재사용
- 토큰과 컴포넌트 목록 자동 생성
- [x] K-AQUAS와 D-ROAD 제품 표현 전환 제공
- [x] 사용 기준, 좋은 사례, 잘못된 사례, 변경 이력 제공
- [x] 공용 앱 셸과 대표 업무 화면 4종 제공

완료 조건: 직원이 별도 도구 없이 사내 URL에서 최신 기준과 실제 렌더링을 확인한다.

## 3. 공용 컴포넌트 구현

우선순위는 다음과 같다.

1. Button, IconButton
2. TextField, Select, Textarea, Checkbox, Radio, Switch
3. Dialog, Modal, Toast, InlineAlert
4. [x] Tabs, Pagination, Tooltip의 CSS·HTML 기준
5. [x] Table 구성 요소와 빈 상태의 CSS·HTML 기준
6. [x] Form, AppShell, 지도 도구 모음의 CSS·HTML 기준

v0.15에서는 4~6의 시각·마크업 기준을 먼저 완성했다. React 패키지 구현과 자동화된
상호작용 검증은 이 단계의 남은 작업이다.

각 컴포넌트에는 실제 동작, 키보드 사용, 접근 가능한 이름, 모든 상태, 사용 규칙과
테스트를 포함한다.

완료 조건: 견본 전용 구현 없이 같은 컴포넌트를 문서 사이트와 제품이 함께 사용한다.

## 4. D-FIND 추가

- 프론트엔드 코드와 핵심 화면 감사
- 제품의 명도와 밀도 결정
- 기존 기준색을 접근 가능한 역할 토큰으로 연결
- 공용 컴포넌트로 대표 화면 구성

완료 조건: 색만 바꾼 테마가 아니라 D-FIND의 업무와 화면 밀도까지 검증한 제품 설정이
완성된다.

## 5. 제품 적용

- 사용자 관리 또는 시스템 설정 화면을 첫 적용 대상으로 선정
- 신규 화면에 공용 시스템 사용
- 수정 빈도가 높은 기존 화면부터 점진적으로 전환
- 제품별 예외와 전환 비용 기록

완료 조건: 세 제품 중 최소 한 제품의 실제 화면이 공용 패키지를 사용하고, 다른 제품에
반복 적용할 수 있는 가이드가 있다.

## 지속 운영

- 변경은 근거, 영향 범위, 이전 방법과 함께 제안한다.
- 자동 검사를 통과한 변경만 병합한다.
- 버전과 변경 이력을 배포 사이트에 표시한다.
- 사용하지 않는 토큰과 컴포넌트는 즉시 삭제하지 않고 사용 현황을 확인한다.
