# 폼 레이아웃 — Core 1차 기준

시각 견본: [`components/form.html`](../components/form.html). 입력 필드의 세부 상태는
[`components/input.html`](../components/input.html)에서 관리한다. 이 문서는 여러 필드를
한 작업으로 묶는 방법을 정의한다.

## 범위

- Core는 섹션, 열, 라벨과 도움말 위치, 오류 전달, 하단 작업 영역과 저장 상태를 정의한다.
- 솔루션은 필드의 종류·순서, 기본값, 검증 규칙, 권한과 실제 저장 API를 정의한다.
- **기본은 1열**이다. 입력 순서와 도움말을 수직으로 읽게 한다. 시작일·종료일처럼
  하나의 정보를 만드는 짧은 필드만 2열 예외로 묶을 수 있다. 2열도 좁은 화면에서는 1열이다.
- 긴 폼은 관련 필드를 섹션으로 묶고 이동 링크를 제공한다. 섹션 제목은 실제 문서 구조의
  제목으로 표시하며 링크의 대상 ID와 일치시킨다.

## 입력과 오류

1. 필드에는 입력 후에도 보이는 라벨을 둔다. 필수 표시는 시각 기호와 실제 `required`
   속성을 함께 사용하고, 폼 시작 부분에서 필수 표시의 뜻을 설명한다.
2. 도움말과 오류는 해당 필드 바로 아래에 둔다. 오류 발생 시 `aria-invalid="true"`와
   `aria-describedby`를 사용해 입력과 오류 문장을 연결한다.
3. 여러 필드에 오류가 있으면 폼 시작 부분의 오류 요약에서 각 필드로 이동할 수 있게
   한다. 오류 요약만 보여주고 필드별 오류를 생략하지 않는다.
4. 라디오·체크박스 그룹은 `fieldset`과 `legend`로 묶는다. 비활성과 읽기 전용을 혼동하지
   않는다. 검토만 허용할 값은 가능한 한 읽을 수 있는 텍스트로 표시한다.

## 저장과 이탈

| 상태 | 표시 | 기본 동작 |
|---|---|---|
| 변경 전 | 상태 문구 없음 | 저장 버튼은 업무 규칙에 따라 비활성 가능 |
| 편집 중 | 저장되지 않은 변경 사항 | 저장 가능, 이탈 시 손실 방지 필요 |
| 저장 중 | 저장 중 | 중복 제출 차단, 입력값 유지 |
| 저장 완료 | 저장 완료 | 저장 시각이나 다음 동작은 제품에서 결정 |
| 저장 실패 | 실패 원인·재시도 | 입력값 유지, 동일 작업 재시도 가능 |

상태는 색만으로 표시하지 않는다. 상태 문구를 작업 버튼 가까이에 놓고, 비동기 결과는
`role="status"` 또는 오류용 알림 영역으로 전달한다. 긴 폼의 작업 영역은 끝까지 스크롤해도
찾기 쉽도록 하단에 유지할 수 있다. 저장되지 않은 변경 사항을 버리고 이동할 때의 확인
흐름은 아직 설계 중이며, 현재 견본에는 실제 이탈 차단 로직이 없다.

HTML의 저장 상태 전환은 **시각 견본**이다. 서버 저장과 인증, 데이터 검증을 수행하지
않는다. 실제 제품에서는 저장 요청의 성공·실패와 권한 상태에 연결해야 한다.

## 공공업무 기준

[KRDS 입력폼](https://www.krds.go.kr/html/site/global/global_08.html)은 1열 정렬을
우선하고 관련된 입력의 다열 배치를 허용한다. 현재 견본은 이를 기본으로 삼은 **드로미의
업무용 기준**이며, 기관별 의무 준수 판정을 의미하지 않는다. 제출 버튼은 우측 하단에,
도움말과 오류는 입력 가까이에 둔다.

## 검토할 항목

- K-AQUAS와 D-ROAD의 실제 입력 순서에 1열 기준과 2열 예외가 맞는지
- 1024·1200·1440·1920px 폭과 200% 확대에서 하단 버튼이 가려지지 않는지
- 서버 오류, 필드 오류, 저장 중 이탈이 함께 발생할 때의 우선순위
- 데이터 업로드처럼 오래 걸리는 작업은 별도의 업로드 패턴으로 다룰지
