# 폼 레이아웃 — Core 기준

시각 견본: [`components/form.html`](../components/form.html). 입력 필드의 세부 상태는
[`components/input.html`](../components/input.html)에서 관리한다. 이 문서는 여러 필드를
한 작업으로 묶는 방법을 정의한다.

## 범위

- Core는 섹션, 열, 라벨과 도움말 위치, 오류 전달, 하단 작업 영역과 저장 상태를 정의한다.
- 솔루션은 필드의 종류·순서, 기본값, 검증 규칙, 권한과 실제 저장 API를 정의한다.
- **1열을 기본**으로 입력 순서와 도움말을 수직으로 읽게 한다. 시작일·종료일,
  비밀번호·확인처럼 한 의미를 이루는 짧은 필드는 충분한 폭에서 2열로 묶을 수 있다.
  D-ROAD 사용자 생성 폼의 비밀번호 쌍이 실제 근거다. 제품 적용 때 기존 필드 순서를
  일괄 변경하지 않고 이 원칙으로 신규 폼부터 설계한다.
- 긴 폼은 관련 필드를 섹션으로 묶고 이동 링크를 제공한다. 섹션 제목은 실제 문서 구조의
  제목으로 표시하며 링크의 대상 ID와 일치시킨다.
- 긴 폼을 다이얼로그에 넣어야 할 때는 [알림 견본](../components/feedback.html)의
  `.dialog--form`을 사용한다. 낮은 화면에서는 입력 영역만 스크롤하고 제목·취소·확정
  버튼을 계속 볼 수 있게 둔다. 입력 순서와 1열 기본·관련 필드 2열 원칙은 유지한다.
  D-ROAD 사용자 추가 창에서 1280×600 유효 화면의 하단 동작이 첫 화면 밖에 있던
  관찰을 고친 결정이다. 필드 종류와 실제 저장 동작은 제품이 정한다.

## 입력과 오류

1. 필드에는 입력 후에도 보이는 라벨을 둔다. 필수 표시는 시각 기호와 실제 `required`
   속성을 함께 사용하고, 폼 시작 부분에서 필수 표시의 뜻을 설명한다.
2. 도움말과 오류는 해당 필드 바로 아래에 둔다. 오류 발생 시 `aria-invalid="true"`와
   `aria-describedby`를 사용해 입력과 오류 문장을 연결한다.
3. 여러 필드에 오류가 있으면 폼 시작 부분의 오류 요약에서 각 필드로 이동할 수 있게
   한다. 오류 요약만 보여주고 필드별 오류를 생략하지 않는다.
4. 라디오·체크박스 그룹은 `fieldset`과 `legend`로 묶는다. 비활성과 읽기 전용을 혼동하지
   않는다. 검토만 허용할 값은 가능한 한 읽을 수 있는 텍스트로 표시한다.

## 저장과 이탈

| 상태 | 표시 | 기본 동작 |
|---|---|---|
| 변경 전 | 견본은 `변경 사항 없음` 표시 | 저장 버튼 비활성 |
| 편집 중 | 저장되지 않은 변경 사항 | 저장 가능, 이탈 시 손실 방지 필요 |
| 저장 중 | 저장 중 | 중복 제출 차단, 입력값 유지 |
| 저장 완료 | 저장 완료 | 저장 시각이나 다음 동작은 제품에서 결정 |
| 저장 실패 | 실패 원인·재시도 | 입력값 유지, 동일 작업 재시도 가능 |

상태는 색만으로 표시하지 않는다. 상태 문구를 작업 버튼 가까이에 놓고, 비동기 결과는
`role="status"` 또는 오류용 알림 영역으로 전달한다. 긴 폼의 작업 영역은 끝까지 스크롤해도
찾기 쉽도록 하단에 유지할 수 있다. 저장되지 않은 변경 사항을 버리고 이동할 때의 확인
흐름은 아직 설계 중이며, 현재 견본에는 실제 이탈 차단 로직이 없다.

기본 폼은 값을 바꾸면 저장 버튼이 활성화되고, 변경 취소는 마지막 저장값으로 되돌린다.
저장 중·완료는 **로컬 시연**이며 서버에 요청하지 않는다. 아래 저장 상태 전환 역시
시각 견본이다. 실제 제품에서는 저장 요청의 성공·실패와 권한 상태에 연결해야 한다.

## KRDS 점검 항목

[KRDS 입력폼](https://www.krds.go.kr/html/site/global/global_08.html)의 1열 우선과
관련 입력의 다열 배치, 제출 위치, 필드별 오류는 **점검 항목**이다. 제품 실측을 먼저
확인한다. 채택 경계는
[`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에 있다.

## 검토할 항목

- 기존 폼을 적용할 때 제품별 필드 순서와 2열 예외가 맞는지
- 1024·1200·1440·1920px 폭과 200% 확대에서 하단 버튼이 가려지지 않는지
- 서버 오류, 필드 오류, 저장 중 이탈이 함께 발생할 때의 우선순위
- 데이터 업로드처럼 오래 걸리는 작업은 별도의 업로드 패턴으로 다룰지

## 인증 화면 — D-ROAD 대표 시안

2026-10-01 소유자가 공통 인증 화면을 먼저 정하고 D-ROAD 시안부터 만들도록 요청했다.
[`components/auth.html`](../components/auth.html)은 **제품별 HTML 인증 조합**이다.
소유자가 제품별 표현을 바탕으로 React 구현을 요청해 인증 조합을 패키지 v0.3.0으로 정리했다.
기존 토큰 값·제품 코드·React 패키지의 승인 범위는 바꾸지 않는다.

### 제품 근거와 디자인 제안

운영 D-ROAD의 로그인은 이메일·비밀번호·Remember me·가입·비밀번호 찾기 진입이다.
가입은 이메일 중복 확인, 비밀번호·확인, 이름·회사·전화번호, 이메일 코드 발송·확인,
필수 개인정보 동의·선택 마케팅 동의가 있다. K-AQUAS는 이메일·이름·비밀번호·확인,
회사 선택·전화번호와 동의 항목이 공통이고 이메일 인증 절차는 화면에서 확인되지 않았다.
D-FIND 현재 제품(DroMii-Co-Ltd/D-FIND main, 2026-10)은 이메일·비밀번호 로그인과
관리자 승인형 회원가입(이름·이메일·12자 이상 비밀번호·확인)이다. 초기 제공 소스의
Google 로그인은 현재 제품에서 쓰지 않는다.

- 로그인 카드 420px, 가입 카드 480px은 검토값이다. 중앙 한 열, 입력 44px, 본문 16px,
  레이블 14px과 기존 간격·반경을 사용한다. 작은 유효 폭에서는 내부 여백과 버튼 배치를
  바꾸고 긴 가입 폼은 문서 전체를 세로로 스크롤한다.
- 제공 D-ROAD 로고와 다크 명도를 유지한다. 기존 인증용 주황 버튼을 작업 화면의
  Core 보라 역할로 연결한 것은 일관성 검토를 위한 제안이다. 새 기준색은 만들지 않는다.
- 계정 → 사용자 → 동의의 세 그룹으로 정리한다. 회사·기관은 D-ROAD의 직접 입력을
  유지한다. 모든 항목 필수 표시, 인증을 먼저 마치게 하는 시안 순서, ‘로그인 상태 유지’
  문구는 최종 제품 정책 확인 전이다. 비밀번호 길이·복잡도와 코드 만료 시간을 임의로 정하지 않는다.
- 오류는 필드 문구와 `aria-invalid`·`aria-describedby`로 연결한다. 제출 오류 요약에서
  해당 입력으로 이동한다. 로그인 실패는 계정 존재 여부를 드러내지 않는 공통 문구다.
- 비밀번호 표시 버튼, 처리 중 중복 제출 차단, 이메일 변경 시 확인·인증 초기화,
  필수·선택 동의와 문서 열기 위치를 함께 검토한다. 정책 문서는 자리만 보여준다.

### 제품별 표현

| 제품 | 화면·명도 | 유지한 인증 방식·차이 |
| --- | --- | --- |
| K-AQUAS | 밝은 카드·기존 파랑, 로그인 / 가입 | 이메일·비밀번호, 회사·기관 선택, 필수 이용약관·개인정보 동의. D-ROAD 이메일 코드 절차·마케팅 동의를 추가하지 않는다. |
| D-ROAD | 다크 카드·Core 보라, 로그인 / 가입 | 회사·기관 직접 입력, 이메일 중복 확인·코드 인증, 필수 개인정보·선택 마케팅 동의, 비밀번호 찾기 진입. |
| D-FIND | 다크 카드·기존 흰색 primary, 로그인 / 가입 | 이메일·비밀번호 로그인, 이름·이메일·비밀번호(12자 이상 도움말)·확인 한 묶음 가입 후 관리자 승인. 가입을 마치면 로그인으로 돌아가 승인 안내와 이메일을 이어 보인다. 로그인 상태 유지·비밀번호 표시·비밀번호 찾기·이메일 인증·동의 항목·통합 계정을 추가하지 않는다. 로그인 실패는 계정 상태를 드러내지 않는 제품 공통 문구다. |

제품 설정은 `auth-preview.js`의 `products`와 `setProduct()`에서 관리하고 공통 마크업과 CSS를
공유한다. `?brand=k-aquas|d-road|d-find&view=login|signup`으로 직접 열 수 있다.
D-FIND는 시연 상태에 `가입 신청 완료`를 더한다. 제품 전환은 입력값·동의·오류·인증 결과와
대기 중 시연을 초기화한다. K-AQUAS 회사 목록은 예시이며, 실제 조직 목록은 연결 전이다.
D-FIND는 제공 `public/logo.png`를 수정 없이 복사해 사용한다. React 패키지 v0.3.0의
D-FIND 프리셋은 아직 Google 방식이며, 패키지 변경을 승인받은 뒤 이 HTML 시안에 맞춘다.

### 시안 사용과 확장 경계

상단 검토 도구에서 제품·지원하는 인증 화면·기본/오류/처리 중 상태를 전환한다.
이메일 중복 확인은 가상 성공, 인증 코드는 `123456`으로 시연하며 실제 발송·계정 요청·
입력 저장은 없다. 비밀번호 찾기는 후속 설계 안내만 보인다. 검토 도구는 제품 적용 시
제외한다. 동의 체크는 실제 약관 동의·가입 제출로 취급하지 않는다.

로고·브랜드·명도와 인증 단계·필드·동의 항목은 제품 설정으로 공급한다. 단일 계정과
SSO는 시각 통일과 별개의 정책이다. React 인증 조합은 `AuthLayout / AuthLoginForm /
AuthSignupForm / PasswordField / GoogleLoginButton`으로 구현했다. API 계약과 사용 예시는
[React 패키지 사용법](../packages/react/README.md#인증-화면-사용)에서 관리한다. KRDS는 기존 입력·오류·도움 접근성 점검 범위를 참조한다.
