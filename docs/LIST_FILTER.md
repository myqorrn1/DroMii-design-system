# 목록 검색·필터 — Core 1차 기준

시각·동작 견본: [`components/table-selection.html`](../components/table-selection.html).

## 제품 코드에서 확인한 사실

- K-AQUAS `frontend/src/pages/AdminPage/UserLog.js`는 이메일·사용자명·IP 주소 중 검색
  기준을 고르고, 입력값을 로컬 목록에 적용한다. 결과가 바뀌면 페이지를 첫 페이지로 돌린다.
- K-AQUAS `UserList.js`는 사용자 검색어를 목록 요청에 전달한다.
- D-ROAD의 서버 페이지네이션과 접속 로그 선택은
  [`운영 프론트 기준 재확인`](../context/05-live-frontends-2026-09-23.md)과
  [`유지할 공통점`](../context/02-keep.md)에 기록된 후보 근거다. 운영 로그인 후의 세부 동작과
  서버 API는 아직 검증하지 않았다.

## Core 결정

1. 입력란 위에 검색 기준과 검색어의 라벨을 항상 표시한다. 검색 버튼으로 적용하고,
   조건 초기화는 검색 기준·검색어·결과를 함께 초기화한다.
2. 적용 후 `전체 N건 · 현재 M건 표시`를 목록 바로 위에 둔다. 결과가 없으면 조건을
   바꾸거나 초기화할 길을 제공한다.
3. 조건을 바꾸면 페이지를 첫 페이지로 되돌리고, 기존 선택은 해제한다. 현재 페이지와
   검색 결과 전체 중 어느 범위가 선택되는지 명시하지 않은 채 선택을 유지하지 않는다.
4. 서버 목록에서는 입력 지연, 취소, 로딩, 실패 후 재시도의 구체적 시점을 제품 API에 맞춰
   정한다. 검색 실패 시 기존 목록과 입력값을 지우지 않고 오류를 알린다.
5. 실제 제품의 검색 실행 방식은 데이터 크기와 API 비용에 따라 즉시 적용 또는 명시적
   제출을 선택할 수 있다. 이 견본은 서버 요청을 대신해 로컬 가상 데이터에 제출 시 적용한다.

[KRDS 표](https://www.krds.go.kr/html/site/component/component_04_11.html)의
정렬·검색·필터 안내는 제품 동작을 검토하는 점검 항목이다. 채택 경계는
[`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에 둔다.

## 제품 적용 전에 확인할 것

- 검색 기준별 API 필드, 부분 일치·대소문자·한글 처리, 개인정보 마스킹
- 서버 페이지 총건수와 현재 페이지, 조건 초기화 시 URL·브라우저 기록 처리
- 로딩·네트워크 실패·권한 부족 상태의 문구와 재시도 동작
- 한 페이지 선택과 전체 검색 결과 선택의 지원 여부
