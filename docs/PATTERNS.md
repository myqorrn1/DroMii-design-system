# 조합 패턴

패턴은 여러 컴포넌트를 실제 업무 순서에 맞게 묶는 기준입니다. 제품마다 데이터는 달라도
같은 종류의 업무가 같은 위치와 동작을 사용하도록 합니다.

## 현재 상태

대표 화면 4종의 기존 시안은 2026-09-23 제거했습니다. 현재 시각 견본은 파운데이션과
개별 컴포넌트, 헤더·메뉴의 앱 셸 구조만 제공합니다. 대표 화면은 Core 디자인이 확정된 뒤
다시 설계하며, 아래 항목은 완료된 화면이 아닌 앞으로 다룰 업무 요구사항입니다.

## 다시 설계할 업무

- **대시보드**: 지표 우선순위, 기간 선택, 변화 표시, 차트, 확인할 일, 데이터 없음과 부분 오류
- **사용자 관리**: 검색·필터, 표 선택, 승인·거절·정지·삭제, 권한 편집, 개인정보 마스킹
- **데이터 업로드**: 파일 선택·검증, 진행 상태, 중복·부분 실패·재시도, 완료 후 다음 행동
- **지도 워크스페이스**: 검색, 레이어·범례, 객체 선택과 정보 패널, 측정 도구, 지도 오류

## 공용 화면 구조 후보

```text
AppShell
├── Sidebar: 주요 업무 이동
└── Main
    ├── Header: 현재 화면 + 전역 동작
    └── Content
        ├── Page title / actions
        ├── Filter or summary
        ├── Primary work area
        └── Feedback / secondary action
```

제품명, 메뉴 내용, 도메인 데이터는 솔루션에서 주입합니다. 위치, 선택 상태, 포커스,
오류 전달과 작업 우선순위는 Core에서 정할 후보입니다. 이 구조도 실제 업무 근거로 검증한 뒤
확정합니다.

## 패턴 추가 기준

1. 한 컴포넌트로 설명할 수 없는 반복 업무인지 확인합니다.
2. 두 솔루션 이상에서 구조가 반복되는지 확인합니다.
3. 정상 흐름뿐 아니라 빈 상태, 오류, 권한 제한, 로딩을 함께 설계합니다.
4. 메뉴와 버튼의 이름보다 사용자의 목표를 기준으로 묶습니다.
5. 확정된 Core로 화면을 조합하고 제품별 표현을 확인합니다.
