# 업무 조합 패턴 — Core 1차 기준

시각·상태 견본: [업무 패턴](../components/workflows.html). 이 페이지는 목록·확인·업로드·지도
주변 제어의 **작은 조합 견본**이며 대표 화면이 아니다. 상태 버튼은 가상 결과만 바꾸고
서버에 요청하지 않는다. 현행 제품에서 확인한 동작과 확장 후보의 구분은
[제품 소스 후속 대조](../context/06-product-audit-2026-09-23.md#2026-09-28-업무-패턴-대조--읽기-전용-후속-확인)에 둔다.

## 설계 순서와 공통 계약

패턴은 제품 코드의 업무 순서를 확인하고, 두 제품에 공통이거나 반복 문제를 해결할 때
Core로 올린다. 공용 구조와 상태는 Core에, 색 조합은 [제품별 설정](THEMING.md)에 둔다.
제품 로고·메뉴·도메인 데이터, 파일 정책, 권한, 실제 API는 솔루션이 정한다.

모든 비동기 패턴은 **정상 / 빈 상태 / 오류 / 권한 제한 / 로딩**을 설계한다. 일부 항목만
성공할 수 있고 서버가 항목별 결과를 제공하면 **부분 성공**을 별도 상태로 둔다. 현재 두
제품의 확인된 목록·업로드 API에는 그런 계약이 보이지 않아 견본의 부분 성공은 **조건부
확장 후보**다. 상태마다 요청과 영향 범위, 데이터의
최신성, 성공·실패 대상, 다음 행동, 초점·상태 알림·입력 보존이 드러나야 한다. 서버 실패를
성공 토스트 하나로 덮거나 부분 결과를 전체처럼 표시하지 않는다. 실제 API에 없는 취소·
복원·재시도는 약속하지 않는다.

## 1. 목록·검색

K-AQUAS 사용자·로그 목록과 D-ROAD 서버 페이지네이션·접속 로그를 근거로 한다.
[표 기준](DATA_TABLE.md)과 [검색·필터 기준](LIST_FILTER.md)을 조합한다.

| 상태 | 화면과 다음 행동 |
|---|---|
| 정상 | 적용 조건, 총건수, 현재 표시 건수와 갱신 시점을 목록 앞에 표시한다. 긴 표는 내부 가로 스크롤과 키보드 초점을 제공한다. |
| 빈 상태 | 데이터 자체가 없으면 생성, 조건에 맞는 결과가 없으면 조건 변경·초기화를 제시한다. |
| 오류 | 조건과 마지막 확인 결과를 보존하고 최신 정보가 아님을 표시한다. 같은 요청만 다시 시도한다. |
| 부분 성공(조건부) | API가 항목별 결과와 누락 건수를 줄 때만 전체·성공·누락 건수를 나누고 누락 항목만 다시 요청한다. 현재 두 제품의 확인된 목록 호출에서는 지원 근거가 없다. |
| 권한 제한 | 결과를 노출하지 않고 필요한 조회 권한을 설명한다. 권한이 없는 행의 존재도 노출하지 않는다. |
| 로딩 | 요청 영역의 진행 상태를 알리고 이전 결과의 최신성 표시를 유지한다. 응답 순서 역전·중복 요청은 제품 구현에서 처리한다. |

선택형 목록은 조건·페이지가 바뀌면 선택을 초기화한다. 전체 선택 범위를 명확히 한다.
제품 API가 부분 결과와 건수를 제공하지 않으면 부분 성공 상태를 억지로 만들지 않는다.

## 2. 위험 동작 확인

제품의 `alert()`·`window.confirm()`과 단건 삭제 흐름을 Core의 다이얼로그·결과 배너로
정리한다. 되돌릴 수 없는 삭제·거절 등에만 확인을 사용한다. 대상 이름·건수, 영향,
되돌릴 수 있는지 여부와 동사를 확정 버튼에 쓴다. 취소는 원래 선택과 초점을 유지한다.

| 상태 | 화면과 다음 행동 |
|---|---|
| 정상 | 대상과 결과를 확인 다이얼로그에 제시하고 `취소`와 구체적인 확정 동작을 제공한다. |
| 대상 없음 | 확정 동작을 노출하지 않고 선택 방법을 안내한다. |
| 오류 | 단건 실패는 대상을 유지하고 원인·재확인 방법을 알린다. 대량 작업이 실제로 생기고 항목별 결과가 제공될 때만 부분 성공을 추가한다. |
| 권한 제한 | 확정 동작을 막고 대상 변경 없이 필요한 권한을 안내한다. |
| 로딩 | 확정 버튼을 중복 실행할 수 없게 하고 결과를 확인할 때까지 진행 상태를 알린다. |

현재 K-AQUAS·D-ROAD에서 확인한 사용자·프로젝트 삭제는 **단건**이다. D-ROAD에 로그
일괄 삭제 API 함수는 있으나 현행 화면에서는 쓰이지 않는다. 실제 로그 보존, 권한, 감사
기록은 제품 정책이므로 견본의 `임시 작업 삭제` 예시를 그대로 업무 명칭으로 옮기지 않는다.

## 3. 파일 업로드

K-AQUAS의 여러 이미지·MP4를 묶은 탐지 시작 요청과 D-ROAD의 TIFF 한 파일 업로드·
**자동 AI 분석 시작**을 근거로 한다. 파일 선택 → 제품 정책 검증 → 전송 → 서버 처리·
분석의 **결과 상태**를 구분한다. 실제 요청 경계는 제품마다 다르며 공용 수동 분석 시작
동작을 만들지 않는다. 파일명·형식·크기·상태는 텍스트로 제공한다. 드래그 앤 드롭을
추가하더라도 키보드로 쓰는 파일 선택을 남긴다.

| 상태 | 화면과 다음 행동 |
|---|---|
| 정상 | 전송된 파일 수·이름과 분석 **시작 요청** 결과를 구분한다. 분석 완료로 오인시키지 않는다. |
| 선택 전 | 허용 형식·크기 등 실제 제품 정책과 파일 선택 방법을 제시한다. |
| 오류 | 요청 범위와 오류를 밝힌다. D-ROAD는 전송 성공 뒤 분석 시작 실패도 별개로 알린다. 재시도 전에 중복 생성 여부를 확인한다. |
| 부분 성공(조건부) | 서버가 항목별 결과를 줄 때만 성공·실패 건수와 각 파일 상태를 표시한다. 현재 두 제품의 확인된 업로드 호출에는 파일별 결과 근거가 없다. |
| 권한 제한 | 전송 전에 차단하고 파일이 서버에 저장되지 않았음을 알린다. |
| 로딩 | 현재 두 제품처럼 수치 진행률이 없으면 `요청 중`을 표시한다. 퍼센트·파일별 완료 건수, 이탈·취소 가능 여부는 실제 API에 맞춘다. |

## 4. 지도 주변 제어

K-AQUAS의 조밀한 지도 제어와 D-ROAD의 지도·관리 패널을 바탕으로, 공통은 레이어 선택,
범례, 도구 상태, 객체 선택 정보, 레이어별 오류 전달까지로 제한한다. 실제 지도 타일·분석
알고리즘·수질/도로 분류는 제품 확장이다. 지도 색만으로 상태를 전달하지 않고 범례의 문장과
선택 객체 정보를 함께 보여준다.

| 상태 | 화면과 다음 행동 |
|---|---|
| 정상 | 레이어 이름·선택 상태, 범례, 선택 객체의 텍스트 정보를 지도 주변에 놓는다. |
| 빈 상태 | 기간·레이어에 데이터가 없음을 알리고 조건 확인 방법을 제시한다. |
| 오류 | 실패한 레이어를 특정한다. K-AQUAS의 일부 위성 목록처럼 기존 지도를 유지하고 다시 시도한다. D-ROAD의 사용자 오류 안내는 개선 제안이다. |
| 권한 제한 | 제한된 레이어를 숨기고 허용된 레이어·도구는 계속 사용하게 한다. |
| 로딩 | 불러오는 레이어 이름을 알리고 이미 표시된 정보의 최신성·조작 가능 여부를 유지한다. |

지도는 마우스 외에 레이어·도구·선택 객체를 키보드로 조작할 경로가 필요하다. 실제 지도
라이브러리에서 초점 순서, 확대, 대체 목록, 좌표 읽기는 제품 적용 때 검증한다.

[필터링·정렬](https://www.krds.go.kr/html/site/global/global_10.html),

[도움](https://www.krds.go.kr/html/site/global/global_02.html)을 참고한다.

파일명·형식·크기 안내만 업로드에 참고하고, 전송 흐름은 제품 코드에서 설계한다.
채택 범위와 예외는 [KRDS 기준 문서](PUBLIC_SECTOR_DIRECTION.md)에만 기록한다.

## 아직 검증할 것

- 실제 API·운영 화면의 항목별 결과, 재시도 단위, 권한 오류와 감사 보존
- 200% 확대, 키보드·스크린리더, 긴 파일명·수치·지명, 느린 연결과 응답 순서 역전
- 지도 라이브러리의 키보드 대체 경로와 실제 운영 레이어 오류

대표 화면은 Core 패턴과 제품별 데이터 경계가 확정된 뒤 다시 설계한다.
