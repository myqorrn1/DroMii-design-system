# 공공업무용 DroMii Core 방향

> 2026-09-23 현재 판단. 이 문서는 K-AQUAS·D-ROAD의 공공기관 실무 사용 맥락을
> 반영한다. 실제 기관의 계약·제안요청서·운영 규격이 확인되면 그 요구사항을 우선 검토한다.

## 적용 맥락과 경계

현재 확인된 주 사용자는 내부 관리자, 수질 분석 담당자, 도로 조사 담당자다. 따라서
Core는 **공공기관 직원이 오래 사용하는 전문 업무 도구**를 우선 설계한다. 시민이
신청·조회하는 공식 정부 누리집과 같은 정보 구조라고 가정하지 않는다.

[KRDS](https://www.krds.go.kr/html/site/utility/utility_02.html)를 공용 컴포넌트의
**기본 설계 기준**으로 삼아 일관성·접근성·오류 예방을 판단한다. 전문 지도·분석 업무에서
KRDS의 패턴을 그대로 적용하기 어려우면 이유와 대체 방식을 기록한다. [행정안전부 설명](https://mois.go.kr/frt/sub/a06/b04/uixInnovation/screen.do)은
KRDS를 공공 웹·앱 UI/UX 설계·구축·운영에 활용하도록 안내한다. 그러나 드로미의
솔루션이 공식 정부 서비스로 운영되는지, 기관별 규격이나 KRDS 준수 의무가 있는지는
아직 확인되지 않았다. **정부 공식 배너·기관 식별자·정부 로고를 임의로 붙이지 않는다.**
필요 여부는 실제 운영 주체와 납품 요구사항을 확인한 뒤 정한다.

## Core 판단 기준

1. **과업 우선:** 사용자가 현재 위치, 다음 동작, 처리 결과를 바로 파악하게 한다.
   장식적인 색 면보다 표·지도·폼·알림의 정보 위계를 우선한다.
2. **오류 예방과 복구:** 필수값·단위·기간·권한을 입력 위치에서 설명하고,
   제출 실패 시 입력값과 작업 맥락을 보존한다.
3. **검증 가능한 상태:** 처리 중·완료·실패·부분 성공을 문구와 형태로 구분한다.
   실제 기록·감사 추적은 제품 요구사항과 서버 기능을 확인한 뒤 설계한다.
4. **접근성:** 키보드 탐색, 본문 건너뛰기, 포커스, 확대, 대비와 대체 텍스트를
   공용 컴포넌트의 완료 조건으로 둔다.
5. **전문가 효율:** 반복 작업의 속도와 데이터 밀도를 고려하되, 조밀한 배치를
   모든 화면의 기본값으로 강제하지 않는다.
6. **DroMii 제품군:** 같은 구조·상태·글자 위계를 공유하고, 제공된 제품 로고와
   기준색은 업무를 방해하지 않는 역할에 사용한다.

KRDS의 공식 배너·기관 식별자 같은 **정부 서비스 신원 요소**는 별도 판단한다.
사용자가 공공기관 직원이라는 사실만으로 드로미 솔루션을 정부 공식 누리집이라고
표시하지 않는다.

## 현재 결과물의 판정

| 유지 | 수정 | 보류·확인 |
|---|---|---|
| HTML·Markdown으로 실제 CSS를 보여주는 관리 방식 | 폼은 1열을 기본으로, 관련된 짧은 필드만 2열 | 기관별 납품 규격과 공식 정부 서비스 여부 |
| 역할 토큰, 라벨·오류 연결, 제품 로고, 헤더·메뉴의 공통 구조 | 반복 메뉴를 건너뛰는 키보드 경로와 좁은 폭·확대 검증 | D-ROAD 다크 기본값이 관리·분석 업무 전체에 적절한지 |
| 제품 기준색과 도메인별 메뉴 차이 | 상태 문구, 단위, 실패 후 재시도와 권한 제한 흐름 보강 | 실제 제품 화면 적용과 React 패키지 |

[KRDS 입력폼](https://www.krds.go.kr/html/site/global/global_08.html)은 기본적으로
1열 정렬을 권장하고, 의미상 연결된 입력이나 충분한 공간이 있을 때 다열을 허용한다.
제출 버튼의 우측 하단 배치와 중복 제출 방지 역시 현재 Core와 맞는다. 이에 따라
`components/form.html`의 기본형을 1열로 바꿨다.

[KRDS 테이블](https://www.krds.go.kr/html/site/component/component_04_11.html)을
기준으로 사용자 표의 날짜를 왼쪽에, 비교할 수치를 오른쪽에 놓고 행별 상세 동작을
명시한다. 일괄 작업이 없는 표에서는 선택 열을 없앤다. 세부 기준은
[`데이터 테이블`](DATA_TABLE.md)에 둔다.

## 다음 검토 순서

1. 헤더·메뉴·폼의 1024·1200·1440·1920px, 200% 확대, 키보드 이동을 검증한다.
2. 검색·필터·긴 표·권한·확인 동작을 공공업무의 반복 패턴으로 정리한다.
3. 업로드의 진행·실패·부분 성공, 지도 도구·범례·객체 선택을 검토한다.
4. K-AQUAS·D-ROAD의 실제 업무 흐름에 Core를 대입해 과도한 공통화와 제품별 예외를
   확인한다. 그 뒤 대표 화면을 다시 만든다.

이번 변경은 **디자인 기준과 HTML 견본**에만 적용한다. 제품 코드, 토큰 값, 로고 형태,
React 패키지는 수정하지 않는다. KRDS 참고가 곧 규정 준수나 접근성 인증을 뜻하지
않으며, 컴포넌트와 완성 화면의 별도 검증이 필요하다.
