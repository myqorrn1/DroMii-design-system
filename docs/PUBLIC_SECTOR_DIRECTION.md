# KRDS 채택 범위와 예외 목록

> 2026-10-02 사용자 결정까지 반영. K-AQUAS·D-ROAD에서 DroMii Core를 추출·리팩토링할 때의
> 참고 범위를 정한다. 단계 2 제품 감사와 단계 3 소유자 선택을 반영한다.

## 목적과 판단 순서

DroMii Core는 K-AQUAS와 D-ROAD의 **기존 디자인을 추출하고 고쳐서** 만든다.
기준색, 제공된 로고, 메뉴 구조와 익숙한 업무 흐름을 유지한다. 접근성 문제, 불일치,
임시방편, 라이브러리 기본값처럼 근거가 약한 부분을 고친다. 새 컴포넌트는 두 제품의
공통점이거나 Core로 올릴 명확한 가치가 있을 때 제안한다.

1. **제품 코드 근거:** 운영 D-ROAD React 소스와 로컬 K-AQUAS 프런트에서 실제 값·구조·동작을 확인한다.
2. **Core 가치:** 두 제품의 공통 부분인지, 공통화하면 반복 문제를 해결하는지 판단한다.
3. **KRDS·접근성 점검:** 관공서 실무자가 쓰는 화면으로서 문제를 검토한다. KRDS의
   항목은 제품 업무에 맞는 것만 선택한다. 채택한 항목에서 다르게 가는 중요한 결정은
   자동으로 버리지 않고 아래 예외 목록에 근거를 남긴다.

KRDS는 **선택적으로 참고하는 점검 자료**이며 전 항목을 채택할 의무가 없다. 유용한
일부 원칙이나 패턴을 적용하더라도 결과는 **KRDS 참고·부분 적용**으로 설명한다. 이
저장소가 KRDS 공식 구현이나 정부 누리집이라는 뜻은 아니다. 현재 견본은 기관별 계약
기준이나 KWCAG 2.2 준수를 검증해 인증받은 결과물이 아니며, 실제 제품 화면에서 별도로
확인해야 한다. 이 경계에 관한 설명은 이 문서에서만 관리한다.

## 접근성 목표와 선택 적용할 KRDS 항목

- KWCAG 2.2 준수를 목표로 포커스, 키보드, 본문 건너뛰기, 대비, 색 이외의 상태 단서,
  대체 텍스트와 화면 확대를 설계·검증한다.
- KRDS의 업무 도구에 해당하는 기본 패턴 7개를 **필요할 때 참고할 목록**으로 둔다:
  **입력폼, 오류, 확인(위험 동작), 목록 탐색, 필터링·정렬, 첨부파일, 도움**. 제품 흐름을
  먼저 확인하고 적합한 세부 원칙만 고른다. 일곱 패턴을 모두 구현해야 하는 것은 아니다.
- 제품 기준색 값은 유지한다. 색상 단계 간 차이로 필요한 명도 대비를 보장하는 규칙은
  토큰의 수치와 검사 방법에 반영한다. KRDS 색상 값 자체는 가져오지 않는다.
- 본문 등 읽기용 텍스트는 행간 150% 이상과 확대에 대응하는 상대 단위를 목표로 한다.
  현행 값과의 큰 차이는 단계 3에서 검토해 승인받은 값으로 적용한다.

[KRDS 타이포그래피](https://www.krds.go.kr/html/site/style/style_03.html)는 상대 단위
행간과 150% 이상을 안내하고, [디자인 토큰](https://www.krds.go.kr/html/site/style/style_07.html)은
명도 모드를 설명한다. 드로미의 실제 값은 제품 감사와 승인 후 확정한다.

## 방식만 참고할 항목

- 제목·본문의 단계와 굵기 구조를 참고한다. 승인된 본문 크기와 `default / compact`
  밀도 축의 예외 근거는 아래 목록에 기록한다.
- 선명한 화면 모드는 이번에 만들지 않는다. `brand / scheme / density` 축을 설계할 때
  고대비 명도 모드가 들어갈 자리만 둔다.
- 컴포넌트 문서는 **구조 / 사용 기준 / 접근성 / 상호작용**의 같은 틀로 작성한다.

단계 3에서는 제품·Core·KRDS의 큰 차이를 별도 문서 없이 보고하고, 소유자가 추천안

[`제품 적용 전략`](APPLICATION.md)에 따라 적용을 계획할 때 기록한다.
