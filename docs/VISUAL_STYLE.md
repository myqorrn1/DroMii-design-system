## 2026-10-02 공통 모달·업로드·부가 창 시안

[세 제품 시안](../components/overlays.html)의 공통 디자인은 소유자가 확정했다. 원본은 `components/base.css`의
Core 구간이며 브랜드·명도만 달리한다. 기존 제품의 업무 항목·필수 여부·지원 형식은 유지한다.

- 제목 왼쪽, 공식 Lucide X 닫기 오른쪽 위, 취소/닫기와 실행 버튼은 하단 오른쪽.
  헤더·본문·하단 여백 24px, 낮은 화면 16px. 긴 폼은 본문만 스크롤한다.
- 짧은 선택·확인은 기존 448px, 입력 폼 480px, K-AQUAS 자료 상세 560px.
  실제 두 자료/3D를 보여주는 기존 창만 720px를 유지한다.
- 선택형은 제목·설명이 있는 왼쪽 정렬 목록 버튼. 입력 라벨은 `.lb`로 통일한다.
  모달 자체에 글자색을 지정해 브라우저 기본 검정이 다크 화면에 들어오지 않게 한다.
- 제품 창의 본문은 `.dialog-stack`으로 항목 사이 16px을 공유한다. `.f`의 필수 표시는
  실제 `required`에 맞추며, 업무용 분석인자 목록의 내부 밀도·순서는 유지한다.
  상세 제목/속성/설명은 `.dialog-summary`·`.dialog-properties`·`.dialog-section`을 쓴다.
  속성 라벨은 가용 폭의 40% 이내·최대 10rem, 값은 나머지 폭을 사용해 긴 라벨과 확대에 대응한다.
  K-AQUAS 사용자 수정·API 설정도 입력 폼 폭을 사용한다. 삭제 확인은 선택한 대상과 목록에서 제거되는 영향을 표시한다.
- `.file-input`은 네이티브 파일 선택을 유지하며 선택 버튼·파일명·보더·포커스를 토큰에
  연결한다. 도움말·오류는 `aria-describedby`, 오류는 `aria-invalid`로 표시한다.
  시안의 파일 목록은 파일명·크기만 표시하며 파일 내용·실제 전송·형식 검증은 처리하지 않는다.
- 소유자 후속 요청으로 현재 업로드 시안은 기본·파일 선택·오류만 제공한다.
  처리 중·권한 제한은 시안에서 제거했으며 재도입은 후속 검토한다.
- 지도 설정·플로팅 부가 창은 `.floating-panel`·`.floating-body`의 16px 여백과
  같은 제목/닫기 구조를 사용한다. 기존 도구 위치·그룹·업무 배치는 유지한다.

K-AQUAS 선택/업로드·상세와 D-ROAD 업로드·D-FIND 프로젝트 생성,
두 제품 레이어 창·K-AQUAS 부가 서랍에 해당 규칙을 연결했다. D-FIND 업로드 구성은
공용 형태 확인용이며 제품의 파일 형식·실제 업로드 흐름을 확정했다는 뜻이 아니다.
React v0.3.3의 기존 `Dialog`도 제목/닫기 구조와 공통 CSS를 사용한다.
새로운 FileUpload·제품 셸·부가 창 React 조합은 추가하지 않았다. 실제 제품 코드는 미수정이다.

## 목표

K-AQUAS와 D-ROAD가 서로 다른 색과 명도로 보여도 헤더, 메뉴, 글자 위계, 컨트롤의
형태와 상태를 보면 같은 DroMii 제품군으로 읽히게 한다. 공공기관 실무자가 지도·표·폼을
오래 사용하는 업무 도구이므로 데이터, 현재 작업, 처리 결과가 장식보다 먼저 보이게 한다.
KRDS 채택 범위와 예외는 [`KRDS 채택 범위와 예외`](PUBLIC_SECTOR_DIRECTION.md)에
기록한다.

## 공통 인상

- **표면:** 페이지·패널·떠 있는 면을 역할별로 구분한다. 일반 영역은 얇은 경계선으로
  나누고, 그림자는 떠 있는 요소에 집중한다. 큰 카드나 색 면으로 화면을 채우지 않는다.
- **글자:** Pretendard를 기본으로, 제목·본문·보조 정보의 위계를 반복한다. 숫자가 많은
  표·지표에는 데이터용 모노스페이스를 쓸 수 있다. 글자 크기를 뷰포트 `vw`로 정하지 않는다.
- **형태:** 작은 컨트롤에는 4px, 큰 떠 있는 면에는 10px 반경을 기본으로 한다.
  임의의 각진/둥근 형태를 화면마다 섞지 않는다.
- **간격:** 기존 4px 단계와 24px 본문 여백을 기본으로 하고, 조밀한 지도 도구는
  별도 밀도 설정을 사용한다. 내용이 많다는 이유로 글자를 작게만 줄이지 않는다.
- **강조:** 제품 기준색은 주요 실행, 현재 위치, 포커스처럼 의미가 있는 곳에 사용한다.
  메뉴마다 색을 따로 주거나 넓은 배경을 기준색으로 칠하지 않는다.

## 앱 셸의 공통 규칙

2026-10-01 소유자가 다음 통합 플랫폼 배치를 승인해 HTML 검토안을 구현했다.
배치 방향 승인이며 최종 시각 승인·제품 적용은 아니다.

1. **단일 공통 헤더:** 현재 솔루션 로고·솔루션 전환, 현재 위치, 알림, 회원명, 로그아웃을 같은 줄에
   둔다. 현재 위치는 구분선·32px 아이콘 칩·라벨/이름 두 줄로 48px 헤더 안에 표시하며 D-FIND는
   선택한 작업까지 › 로 잇는다. 오른쪽 끝은 [사람 아이콘 + 회원명(제품 기준 글자색)]
   [로그아웃 아이콘 + 로그아웃]으로 세 제품을 통일한다. 계정 펼침 메뉴와 헤더의 관리자 페이지
   이동은 두지 않는다. 관리 업무 이동은 레일 하단 관리가 맡는다(2026-10-08 소유자 결정). 납품 솔루션의 헤더에는 별도 DroMii 로고·텍스트를 표시하지 않는다. 기존 제품 헤더와 합치며 별도 전역 바를 쌓지 않는다.
   K-AQUAS의 지도 위 유역·레이어 카드는 최신 소유자 결정에 따라 기존 위치에 유지한다.
   2026-10-02 소유자 결정으로 K-AQUAS 헤더의 분석 유역 선택은 제거하고 재도입은 보류한다.
   지도 카드의 유역 정보·레이어 제어는 유지한다.
2. **제품별 업무 탐색:** K-AQUAS 기능 레일, D-ROAD 프로젝트 계층·운영관리 진입,
   D-FIND 프로젝트·지장물 탐지·변화 탐지·측정·보고서 순서를 보존한다. 같은 메뉴
   항목을 강요하지 않고 행·선택·hover·focus 규칙을 공유한다. 선택은 색·굵기·표시선으로 전달한다.
   D-FIND는 프로젝트 선택에서 시작한다. 선택 전 레일에는 프로젝트(와 관리)만 두고, 프로젝트를
   고르면 지장물 탐지·변화 탐지·측정·보고서를 프로젝트 아래에 짧은 페이드로 나타낸다. 선택을
   해제하면 다시 숨긴다. 현재 D-FIND가 프로젝트 없이 업무 패널을 열지 않는 동작에 맞춘 제품 확장이며
   항목 순서와 위치(프로젝트 맨 위·관리 맨 아래)는 바꾸지 않는다.
3. **접히는 작업 패널:** 현재 기능의 필터·목록을 넣는다. 접으면 지도를 넓히고,
   명확한 다시 열기 제어에 초점을 돌려준다. 좁은 폭에서는 지도 위에 겹치며,
   가려진 본문은 `inert`로 키보드·접근성 탐색에서 제외한다. 패널 안 Esc는 접기,
   본문 건너뛰기는 패널을 접고 본문으로 이동한다. 레일·헤더는 계속 접근할 수 있다.
   K-AQUAS 위성·전국조사는 기존처럼 별도 왼쪽 패널 없이 작업 공간을 채운다.
4. **본문 슬롯:** 지도형은 카드 여백 없이 남은 공간을 채운다. D-ROAD의 지도 아래
   결과 줄은 제품 확장이다. D-FIND 보고서는 지도 자리를 대체하고 작업 레일을 유지한다.
   관리형은 표·폼에 맞는 별도 여백을 사용한다. K-AQUAS·D-ROAD는 관리 탐색을 두고,
   D-FIND 회원 관리는 공통 레일만 유지하고 별도의 좌측 관리 목록은 두지 않는다.
5. **헤더 상호작용:** 솔루션 전환·알림은 네이티브 펼침, 로그아웃은 바로 누르는 버튼으로 구성한다.
   한 번에 하나를 열고 바깥 클릭으로 닫는다. Esc로 닫으면 원래 제어에 초점을 돌린다.
   로고에는 제품명, 현재 솔루션에는 접근 가능한 이름과 선택 상태를 제공한다.

검토 치수는 세 제품 헤더 최소 48px(데스크톱 기본 화면 실측 49px), 작업 패널은 세 제품 모두 280px,
레일은 세 제품 모두 72px이다. 2026-10-02 소유자 요청으로 D-ROAD 320px·D-FIND 360px을
K-AQUAS의 280px에 맞췄다. `components/base.css`의 `--ps-panel-width` 한 곳에서 관리하고
제품별 JS 폭 설정은 두지 않는다. 좁은 화면에서는 가용 폭까지 줄이는 기존 규칙을 따른다.
이는 **시안 치수**이며 새 파운데이션 토큰 확정이 아니다. 관리 메뉴는 기존
248px Core 검토값을 쓴다. 좁은 폭에서 헤더 맥락은 다음 줄로 감싸고 관리 메뉴는
본문 위로 옮긴다. 본문 16px, 좁은 작업 패널 14px은 승인된 밀도를 사용한다.

HTML 원본은 `components/navigation.html`, 시연 설정·상호작용은
`navigation-preview.js`, 스타일은 `base.css`의 앱 셸 구간이다. 상단 검토 도구는
제품 헤더가 아니다. K-AQUAS는 소유자의 전체 메뉴 구현 요청으로 아래 작업 배치까지
확장했다. D-ROAD·D-FIND는 아래 제품 근거에 맞는 작업 패널을 추가했으며 지도 엔진·보고서 본문·관리 표는 슬롯이다. 솔루션 전환은 가상 화면 전환이고 SSO·제품 이동·알림·로그아웃·
실제 데이터/API 연결이 아니다. React 앱 셸은 HTML 시각 검토 후 만든다.

## 2026-10-02 D-ROAD와 D-FIND 셸 공통 스타일

소유자가 두 제품 셸 시안 정리를 요청했다. K-AQUAS에서 승인한 헤더·선택/hover/focus·
지도 도구·모션 규칙을 HTML 셸에서 공유한다. 기존 제품의 색과 업무 탐색을 유지하며
K-AQUAS의 업무 메뉴 항목을 다른 제품에 강제하지 않는다. 지도 도구 위치는 후속 소유자
요청으로 아래 [공통 배치](#2026-10-02-지도-도구-공통-배치)에 맞췄다.

- **D-ROAD:** 운영 소스 감사와 [운영 화면 관찰](../context/06-product-audit-2026-09-23.md#2026-09-29-d-road-운영-셸-시각-확인--읽기-전용)에 따라
  왼쪽 프로젝트/운영관리 전환·그룹 검색·프로젝트 계층·그룹별 업로드·하단 그룹 생성을
  유지한다. 지도 아래 조사 결과 줄도 유지한다. 목록 본체만 스크롤하고 생성 버튼은
  하단에 둔다. 다크 표면·보라 강조와 같은 Core 입력·버튼·모달 표현을 사용한다.
- **D-FIND:** 제공 소스 `MapSidebar.tsx`, `ProjectExplorer.tsx`, `AnalysisPanel.tsx`,
  `ChangeDetectionPanel.tsx`, `MeasurementsPanel.tsx`, `ReportExportSidebar.tsx`를
  읽어 작업 패널(당시 360px, 현재 공통 280px)을 구현했다. 최초의 지도 위 플로팅 배치는 아래 소유자
  공통화 결정으로 고정 레일·인접 패널로 대체됐다. 내부 필터/결과 근거는 유지한다.
  프로젝트·지장물 탐지·변화 탐지·측정·보고서의 기존 순서와 필터/결과 영역을 유지한다.
  보고서는 지도 자리를 대체하고 레일·설정 패널을 유지한다. 회원 관리는 공통 레일만
  유지하며 별도의 관리 목록 패널을 추가하지 않는다. 다크·녹색 강조와 **흰색 primary 버튼**을 유지한다.
- **지도 도구·좁은 화면:** 최초의 D-FIND 상단 가로 도구/하단 이동 도구와 D-ROAD
  단일 측정 진입은 후속 소유자 요청으로 [공통 배치](#2026-10-02-지도-도구-공통-배치)로 대체했다.
  제품 패널과 측정 선택 동기화·보기 모드 유지·레이어 닫기/초점 복귀는 유지한다.
  좁은 화면에서는 작업 패널이 본문을 inert로 가리고 날짜 입력을 한 열로 전환한다.
- **공통 모션:** `.platform-page`의 `--ps-motion-control` 150ms·`--ps-motion-panel` 200ms와
  같은 easing을 사용한다. 업무 전환·패널·양식·헤더 메뉴·툴팁 등장에 적용하며 닫기와
  접근성 상태를 지연하지 않는다. reduced-motion에서는 모두 끈다.

프로젝트 검색·선택, 측정 선택, 변화 요약 전환, 패널 접기와 생성/업로드 양식은 가상
시연이다. 날짜·탐지 대상은 입력 표현만 확인하며 실제 필터 계산·분석·지도·위치 권한·

## 2026-10-02 지도 도구 공통 배치

소유자 요청으로 D-FIND·D-ROAD의 지도 도구를 K-AQUAS 배치에 맞춘다. 2D/3D만 가로로
유지하고 나머지 지도 위 버튼은 세로로 놓는다. 업무 패널 안의 제어는 이 규칙의 대상이 아니다.

  D-FIND 전체화면은 마지막에 유지한다. D-ROAD에도 같은 공통 도구 견본을 추가한다.
  D-ROAD에 2D/3D나 도메인별 레이어 기능까지 새로 구현한 것은 아니다.
- 2026-10-08(v0.29.0): D-FIND는 실제 제품에 있는 도구만 둔다. 레이어 → 거리 도구·영역 도구 →
  확대·축소·내 위치·전체화면이며, 측정 지우기·화면 캡처·레이어 초기화는 D-ROAD 견본에만 남긴다.
- 공용 CSS에서 가장자리 `--ps-map-edge` 20px, 상단 보기 제어 20px, 도구 시작 90px을
  관리한다. 그룹 사이 16px, 내부 여백/간격 4px, 기본 버튼 44px과 4px radius를 공유한다.
  지우기 앞과 위치 앞의 구분 간격 12px·구분선도 세 제품이 같다. 글자 확대에 따라 버튼이
  커지면 레이어 창의 도구 옆 간격도 계산된 그룹 폭을 따른다.
- D-FIND 2D/3D는 지도 오른쪽 상단 가로 그룹이다. K-AQUAS 배경 지도와 같은
  가장자리/상단 기준을 쓴다. 좁은 화면은 가장자리 8px·상단 보기 64px·도구 시작 140px이다.
- 높이가 부족하면 도구 묶음 내부만 스크롤한다. DOM과 Tab 순서는 위에서 아래이며
  키보드로 마지막 버튼까지 접근할 수 있다. 클릭으로 전체 도구를 재렌더하지 않는다.

  따른다. 두 제품 레이어 창은 도구 왼쪽에 16px 간격으로 열고 도구 시작 높이에 맞춘다.
  가용 지도 폭/높이 안에서 줄이고 내부 스크롤한다. 12px 내부 여백·6px radius·역할별
  배경/보더/그림자는 기존 플로팅 창 규칙을 따른다.
- 두 제품 거리/면적은 배타 선택이며 D-FIND 작업 패널과 동기화한다. 지우기/초기화는
  시연 선택 상태를 해제한다. 레이어는 밖 클릭/닫기/Esc로 닫고 Esc는 진입 버튼으로
  초점을 돌린다. 제품 색·공식 아이콘·150/200ms 모션과 reduced-motion은 유지한다.

범위는 HTML 셸의 시각·메모리 상태 시연이다. 지도 엔진·측정 계산·지도 레이어·실제 캡처·
위치 권한·전체화면 실행·React 셸·제품 코드는 연결하지 않는다. K-AQUAS 분석 유역 선택은

## 아이콘 출처와 사용 기준

2026-10-02 소유자 지시: 에이전트가 직접 그린 아이콘을 사용하지 않는다.
K-AQUAS 업무/처리 메뉴는 기존 제품 자산을 보존하고, 관리·알림·프로필·검색·지도 도구·선택 화살표·
비밀번호 표시에는 D-FIND에서 사용 중인 **Lucide 0.468.0 공식 도형**을 사용한다.
벡터 형식 자체의 금지가 아니라 직접 제작한 아이콘의 금지다. 도형 좌표를 고치거나
서로 합쳐 새 아이콘을 만들지 않는다. 색·크기·선 두께는 기존 Core 규격을 따른다.
지도와 차트의 데이터 도식은 기능 아이콘과 구분한다.

원본은 `assets/icons/lucide/source.json`에 패키지·버전·파일·SHA-256·도형을 기록하고,
ISC 라이선스를 함께 보관한다. `npm run icons:build`가 HTML 및 React 아이콘을 생성하며
`npm run check`는 원본과의 동기화를 검사한다. 필요하면 설치된 동일 버전의 공식 npm
패키지를 `node scripts/import-icons.mjs <lucide-react 패키지 경로>`로 다시 읽는다.
아이콘 추가도 공식 원본에서 가져오고, HTML/React 경로를 직접 그리지 않는다.
React 공개 Core 이름 12개와 기존 크기·라벨 계약은 유지한다. 선택 화살표는 공식
24 viewBox가 선명하게 보이도록 16px 영역에서 렌더링하며 입력 높이·배치는 유지한다.

## 세 솔루션 지도 도구의 공통 디자인

2026-10-01 소유자 정정: 통일 대상은 K-AQUAS 내부만이 아니라 **K-AQUAS·D-ROAD·D-FIND 전체**다.
같은 역할의 요소는 같은 형태·아이콘·상태·조작 규칙을 사용한다. 컬러·명도·배치·기능 구성은
제품별로 달라질 수 있다. 제품의 업무 흐름을 같은 배치로 복제하는 것은 통일의 조건이 아니다.

- 지도 아이콘 버튼은 최소 44×44px(2.75rem), 반경은 기존 `radius-sm` 4px이다.
  지도 패널의 compact 설정이 클릭 영역을 줄이지 않게 한다. 아이콘은 24 viewBox,
  표시 20px(1.25rem), 선 2px, `currentColor`로 공유한다.

  선택은 제품 강조색·옅은 배경·경계·작은 표시점과 `aria-pressed`로 전달한다.
  실행 버튼(확대·초기화·캡처·창 열기)에는 선택 상태를 붙이지 않는다.

  화면 경계를 넘지 않게 한다. 제품·업무 전환 시 남은 툴팁을 정리한다.
- K-AQUAS의 좌측 이동·유역 카드, 우측 배경 지도·레이어·측정 그룹은 기존 영역을 유지한다.
  커진 클릭 영역이 카드와 겹치지 않도록 카드에 최소 이격만 준다. 배경 지도는 공통
  아이콘과 짧은 일반/야간/위성 문구를 함께 쓰는 선택 변형이다.

  결과와 D-FIND의 보고서 전환은 그대로다. 두 제품의 전체 지도 도구 목록·도메인 본문을
  완성했다고 표시하지 않는다. 실제 기능이 연결될 때 필요한 도구만 이 규칙으로 구성한다.

`navigation.html`의 `dm-map-*` SVG 심볼, `map-tools-preview.js`의
버튼·아이콘·배경 지도 렌더러와 툴팁이다. 제품 스크립트는 배치·기능·상태만 주입한다.

## D-FIND 장점을 K-AQUAS에서 시험하는 시안

2026-10-01 소유자는 공통 원본 개선을 필수로 정하지 않았다. 기존 D-FIND의 장점을
**K-AQUAS HTML에서 먼저 시험 → 효과 검토 → 필요한 부분만 공통화**하는 순서를 요청했다.
이 절의 표현은 Core 신규 기준이나 다른 제품에 적용한 결과가 아니다.

- 기존 메뉴·원본 사이드 아이콘·카테고리별 위치·그룹·순서·하단 실행·펼침 목록을 유지한다.
  패널 안의 제목·보조 정보·구분선·여백과 목록 선택 표현을 정리한다.
- 우선관리지역·오염원탐지는 기존 펼침 목록을 행으로 정돈하고 이름을 먼저, 날짜·분류를
  보조 정보로 표시한다. 선택은 옅은 배경·표시선·`aria-current`로 구분한다.
  선택한 항목을 지도 가상 표시·상세 창·다운로드 진입에 일치시키며 실제 API는 연결하지 않는다.
- 기존 상세 모달은 항목 이름 → 속성 → 설명 순서로 정리한다. 기존 시연의 날짜·분류만
  사용하며 근거 없는 분석 수치를 추가하지 않는다. 모달 위치와 닫기 동작은 유지한다.
- 지도 도구는 종류·동작을 보존한다. 2026-10-02 소유자 요청으로 좌측 상단 이동·초기화
  도구를 우측 캡처 아래 별도 가로 그룹으로 옮겼다. 확대/축소와 위치/초기화 사이,
  거리/면적과 지우기/캡처 사이의 구분선은 유지한다. 레이어 목록에 표시 개수/전체 개수를 보여준다.
- 반투명 표면과 작은 글자는 가져오지 않는다. 승인된 토큰 값·공용 컴포넌트·React 패키지는
  유지한다. `base.css`의 K-AQUAS 셸 범위와 `navigation-k-aquas.js`만 시각·상태를 담당한다.

시각 검토 후 선택할 것은 목록·상세·도구 그룹의 이 표현을 유지할지 여부다. 다른 솔루션의
배치·전체 업무 화면 변경, 공용 컴포넌트 승격, 토큰 변경은 이번 시안에 포함하지 않는다.

### 2026-10-02 K-AQUAS 지도 공간 후속 검토

소유자가 **현재 헤더·메뉴·지도 도구·모션 규칙을 승인**했다. 이 네 영역은 후속
공통화와 React 셸의 디자인 기준으로 사용한다. 제품별 전체 업무 화면까지 승인한 것은 아니다.

헤더의 세로 여백을 8px에서 4px으로 줄이고 분석 유역 드롭다운을 제거했다.
지도를 우선하는 소유자 요청에 따른 K-AQUAS 시안 변경이며 다른 제품의 헤더는 유지한다.
업무 원본 아이콘과 관리자/처리현황 하단 그룹을 유지한다. 메뉴 표시는 위 공통 결정이 우선한다.
좌측 확대/축소 그룹을 옮긴 뒤 남은 예약 공간을 제거해 영주댐·레이어 목록 카드의
지도 왼쪽 간격을 70px에서 20px로 줄인다. 위쪽 간격 20px와 카드 내용·폭은 유지한다.
좁은 화면은 기존 왼쪽 8px·위쪽 140px 배치를 유지해 지도 선택/도구와 겹치지 않게 한다.
우측 도구는 레이어 → 측정/캡처 → 이동/초기화 순이다. 최신 소유자 요청으로 마지막
확대·축소·위치·초기화 4개도 **캡처 아래 세로 그룹**으로 배치한다. 44px 버튼 크기를
유지하며 짧은 창에서는 도구 영역 안에서 스크롤한다. 선택 상태와 실행 동작의 구분을
유지하고, 조작 뒤에도 도구 DOM·스크롤 위치·초점이 이어지게 한다.

추천안 적용 요청에 따라 큰 그룹 면을 `surface-sunken`에서 더 연한 `surface-page`로
바꾸고, 탭 아래와 목록 바깥의 중복 구분선을 제거했다. 항목 사이·패널 경계·하단 실행의
구분선과 기존 업무 배치·글자 크기는 유지한다.

D-FIND 제공 소스의 `src/shared/components/uiStyles.ts`는 버튼·입력·아이콘 버튼에
`transition duration-150`, `src/shared/styles/map.css`는 지도 도구에 `duration-200`과
누를 때 1px 이동을 쓴다. `MapSidebar.tsx`의 메뉴 전환과 `SelectField.tsx`의 200ms
화살표 회전도 참고했다. K-AQUAS 시안의 버튼·입력·메뉴·목록은 150ms, 지도 도구와
목록 화살표는 200ms 전환한다. 패널·서랍·모달·헤더 메뉴·툴팁의 짧은 등장 모션은
이 속도감으로 확장한 제안이며 D-FIND 원본에 동일 keyframes가 있는 것은 아니다.

업무·하위 탭 전환과 패널 열기에만 등장 모션을 재생한다. 체크·확대·검색 재렌더는
패널을 다시 페이드하지 않는다. 닫기와 초점·inert 변경은 즉시 처리하며 애니메이션 완료를
기다리지 않는다. 지도 본체와 기존 업무 배치는 움직이지 않는다.
`prefers-reduced-motion: reduce`에서는 이 시안의 전환·등장·누름 이동을 끈다.
현재 모션은 위 두 제품 확장까지 세 제품 HTML 셸에서 공유한다.
일반 Core 모션 토큰·React 연결은 후속 작업이다. 제품별 컬러·배치·업무 기능은 각 제품에 맞게 유지한다.

CSS는 `base.css`의 K-AQUAS 업무 조합 구간에 있다. 기존 셸도 같은 JS 원본을 사용한다:
업로드·분석 생성 2단계·지도 자료 상세·처리 서랍·위성 4개 범례. 차트/국유지 상세는 이 시안에서
독립적으로 검토하며 셸에 제품에 없는 진입점을 추가하지 않는다. 파일 내용·실제 영상·지도·
작업 취소는 연결하지 않는다. 공통 업로드 시안에서 제거한 처리 중/권한 제한 옵션을 복구한 것이
아니며 제품에 이미 존재하는 처리 현황만 다룬다.

제품 원본 범례의 남세균 단위 `cells/m²`와 99,999~1,000,000 사이 미표기 구간은 그대로
남겼다. 분석 자료 생산자의 확인 없이 단위·구간을 임의로 고치지 않는다. `장마후` 프리셋의
비활성 `altitude` 키도 활성 14개 인자 목록에 넣지 않는다. 수치·범례의 과학적 정확성 인증은
이번 디자인 검증 범위에 포함하지 않는다.

**2026-10-06 분석인자 선택 높이 개선:** 우선관리지역 생성과 독립 분석인자 창은 폭 720px,
높이 `min(520px, 100dvh - 48px)`을 사용한다. 데스크톱은 2열 카드, 유효 폭 600px 이하에서는
1열이다. 선택된 카드는 체크 표시와 옅은 강조 배경·보더를 함께 사용한다. 프리셋/선택 수,
수동 합계와 오류, 하단 동작은 남기고 14개 인자 목록만 내부 스크롤한다. 낮은 화면에서는
간격을 줄이며 오류 표시 시 중복 안내를 숨겨 목록의 조작 공간을 확보한다.
기본정보 단계는 본문만 스크롤하고 분석인자 선택 버튼을 하단에 둔다. 두 단계 왕복 시
초안·선택·가중치를 보존하며 취소/X/Esc는 닫고 배경 클릭은 닫지 않는다.
기존 프리셋·자동 분배·수동 범위/합계 제한은 유지하고 실제 분석 요청은 보내지 않는다.

이번 조합은 HTML 디자인 시안이다. 기존 Core 승인을 새 제품 조합의 최종 승인으로 확대하지
않는다. React v0.3.3은 CSS를 동기화했으며 전용 업로드·인자·분석 상세·차트·작업 API는 없다.

## 검토 순서

1. 헤더와 메뉴의 라이트·다크, 선택·hover·focus·disabled, 긴 이름과 좁은 폭을 확인한다.
2. 버튼·폼·알림·표에 같은 글자 위계와 표면 규칙을 적용한다. 폼의 섹션·오류·저장 상태는
   [`폼 레이아웃`](FORM_LAYOUT.md)에서 관리한다.
3. 지도·차트·업로드의 업무 상태를 설계한다.
4. Core와 솔루션별 확장이 확정되면 대표 화면을 다시 제작한다.
